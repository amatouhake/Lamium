The screen files split by L-134 Split SettingsScreen.cpp (2026-10-11) are
larger than at the split: `SettingsScreen.cpp` 1,371 to 1,993 lines,
`SchematicsView.cpp` 1,380 to 2,370, `SettingsTableView.cpp` 996 to 1,527
(2026-11-24). No test reaches them. Behavior does not change in this item.

## Decided
- Each view keeps its own state in its own file (L-134); no context struct
  passed everywhere.
- Pure header with tests first, then the call site switches to it; one step
  per commit, build `Lamium` and run `LamiumTests` after each.
- A step that would change a look, a key or which mode wins stops and goes
  to Open.

## Open
- The screen's modes are separate switches and three places order them
  differently. The frame (input and drawing): row page, calculator, world
  map without the waypoint prompt, waypoint prompt, schematic menu, area-save
  prompt, HUD editor, tool view or table. The wheel: row page, calculator,
  schematic menu, world map without the prompt, HUD editor, tool view,
  table. So under either prompt the wheel still scrolls the view the
  navigation shows, unseen, and the menu and the map swap places (whether
  both can be open together is not established). The key listener has a
  third chain. One order for all three changes what the wheel does under a
  prompt: the maintainer's call.
- Where a feature's screen lives. Schematics, Waypoints, Shapes and the
  enchantment pages are in `src/ui`; the world map, the item list and the
  plan view are in their feature folders. No rule says which.
