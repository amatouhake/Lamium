# L-399 Screens: one view shape, a tested mode order, logic out of the screen files

Kind: Refactor **(strong model)**
Status: Open

The screen files split by L-134 Split SettingsScreen.cpp (2026-10-11) are
larger than at the split: `SettingsScreen.cpp` 1,371 to 1,993 lines,
`SchematicsView.cpp` 1,380 to 2,370, `SettingsTableView.cpp` 996 to 1,527
(2026-11-24). No test reaches them. Behavior does not change in this item.

## Decided
- Each view keeps its own state in its own file (L-134); no context struct
  passed everywhere.
- Pure header with tests first, then the call site switches to it; one step
  per commit, build `Lamium` and run `LamiumTests` after each.
- A step that would change a look, a key or which mode wins stops and goes
  to Open.

## Open
- Where a feature's screen lives. Schematics, Waypoints, Shapes and the
  enchantment pages are in `src/ui`; the world map, the item list and the
  plan view are in their feature folders. No rule says which.

## Next
1. Shapes, Waypoints and Schematics behind one table of function pointers,
   as `row_pages::Page` does for the four row pages, so the screen's core
   stops naming them in if-chains (input, wheel, editing keys, render).
2. Which mode takes the frame's input and drawing (row page, calculator,
   world map, waypoint prompt, schematic menu, save prompt, HUD editor, tool
   view, table) as one pure function with tests. The render, wheel and key
   chains each write the order today; unify them only where they agree for
   every pair of modes that can be open together.
3. `SchematicsView.cpp`: row building, the per-field edit rules and the
   click and key routing into pure headers with tests; placement operations
   (delete with the selected index kept, bulk delete, visibility, rotation,
   mirror, layers) into `src/features/schematic`.
4. `drawSchematicsBody` (about 990 lines), `renderTable` and
   `recipes::itemList`'s `drawList` (735 lines) cut by tab or region once
   their decisions are out.

## Known
- `src/ui/RowPages.h` holds the row pages' shape; `SettingsScreen.cpp`
  drives them in one block of its render.
- `SettingsScreen.cpp` names the three list views in 75 lines;
  `SettingsTableView.cpp` draws their undocked content.
- `schematics_view::release()` and `drag()` run every frame whatever view is
  shown; `endEditing`, `reset` and the "is a number being typed" question go
  to every view, the rest to the shown one.
