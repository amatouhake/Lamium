grown past their size at the split when this item began (`22d73965`):
`SettingsScreen.cpp` 1,371 to 1,993 lines, `SchematicsView.cpp` 1,380 to

## Decided
- Each view keeps its own state in its own file (L-134); no context struct
  passed everywhere.
- Pure header with tests first, then the call site switches to it; one step
  per commit, build `Lamium` and run `LamiumTests` after each.
- A step that would change a look, a key or which mode wins stops and goes
  to Open.
- One order for every input, the frame's (maintainer 2026-11-26): row page,
  calculator, world map without the waypoint prompt, waypoint prompt,
  schematic menu, area-save prompt, HUD editor, tool view or table. Under
  either prompt the wheel does nothing. The schematic menu and the world
  map are never open together; the key listener already gives keys in this
  order for every pair that can be open.
- A screen lives with its feature when the feature has a folder: Waypoints
  in `features/map`, Schematics in `features/schematic`, the enchantment
  pages in `features/inventory` (moved 2026-11-26), as the world map, the
  item list and the plan view already were. `src/ui` keeps the settings
  screen's own parts (table, sidebar, row pages, HUD editor, calculator),
  shared widgets and layout, and Shapes, whose data is in `src/overlay`.
