# L-339 Toasts and the settings screen

Kind: Design (Bug: from the 2026-11-14 code review; built, one choice open)
Status: Built 2026-11-17 on `night/L-339`, not checked in game

The HUD draws only while the settings screen is closed, so a toast raised
while it is open runs out unseen. Two different cases hide behind that
(maintainer 2026-11-17): results of what the player does inside the screen
should not be toasts at all, and notices from outside should wait.

## Decided
- DESIGN.md "Passing notices" holds the rule: a toast is for what the player
  did outside a Lamium screen or what came from outside; a result of the
  player's action inside a screen goes to the screen's status line
  (`screen::setInfo` / `setMessage`) or a place on its page.
- Every `showMessageToast` / `showWarningToast` reached from the settings
  screen and its views (a waypoint added from the map's prompt, a saved map
  deleted, the schematic menu's notices, ...) moves to the status line.
- A message or warning toast raised from outside while the screen is open
  (death layout restore, waypoint reached, a background save finished,
  skipped server packs, highlight capped, ...) waits and starts its time
  when the screen closes; one older than 60 s is dropped. An on/off toast
  never waits. The waiting is a pure header with tests.
- A notice the open page already shows (the Saved data page's merge report)
  stays where it is.

## Known
- Inside the screen, only two results were still toasts: a waypoint added
  from the world map's prompt (now the map's notice box) and the schematic
  radial menu's switches (now only the item's on/off). The saved map's
  deletion and "version copied" already used the screen's notices.
- `holdToasts` follows the settings screen's scene; `ToastHold` (Toast.h)
  holds at most 8 and the HUD starts the next when the shown one ends.

## Open
- The radial menu's other notices ("the feature is off", "no area chosen",
  "save started") still go through the toast and now wait for the menu to
  close. Whether the menu should show them itself is not decided.

## Next
In game: a death layout restore or a waypoint reached while the settings
are open shows after closing; a waypoint added from the world map's prompt
says so on the map.
