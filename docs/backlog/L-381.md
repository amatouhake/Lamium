# L-381 Place a recipe while the pointer holds something

Kind: Research
Status: Open, not started

Lamium lays a recipe in as a hand would: each ingredient taken onto the
pointer and put down in its cell (`RecipePlace.cpp`). With something on
the pointer it cannot, so a press that would place shows the recipes
instead. The game's recipe book places with the pointer full, by one
request of its own that does not go through the pointer (maintainer
2026-11-21, while checking [L-379](done/L-379.md)). The aim: every press
behaves as without the pointer's stack, which stays where it is.

## Open
- The game's own way: in the SDK, `CraftingScreenController`'s
  `_handleRecipeSelect` and `_handleCraftItem`, `_recipeAutoCraft`,
  `CraftingContainerManagerController::mSelectedRecipe`, and the
  `CraftRecipeAuto` request data. Which one lays a recipe in from a
  recipe of the game's (not a recipe book cell), with the pointer full,
  and whether a server accepts it. Not tried yet.
- If it does, whether "place" moves to it altogether: one request in
  place of two slot calls a cell.
- Decided for when it works: Ctrl + press with the pointer holding
  another item, or the product with no room, lays the round in and does
  not craft (maintainer 2026-11-21); no stack is set down.

## Next
A trace build (`craft_trace`) trying the candidates on the crafting
table with the pointer full; a short report.
