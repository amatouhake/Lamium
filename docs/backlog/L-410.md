# L-410 Sneak Placement "Send only" lets the client open a door the server keeps shut

Kind: Research (Bug)
Status: A built (the flag for one call), not checked in game

With Sneak Placement on and the method "Send only" (the default), a right
click on a door with an item in hand opens it on the client only: walking
through pulls the player back as if it were shut. With a block in hand the
block is placed and the door still opens on the client.

## Known
- Seen in game (maintainer 2026-11-26, `15c6c182`): "Send only" with a spawn egg and with a block, the door
  opens on the client and not on the server; "Crouch briefly" with a spawn
  egg, the door stays shut on both.
- "Send only" puts the sneak bits on the sent auth input alone
  (`SneakPlacementSend`); the local player's own sneak flag stays off, so
  the client's `useItemOn` runs as an ordinary use while the server runs a
  sneaking one. The first plan of L-293 Place on interactive blocks as if
  sneaking had the client's flag set inside `useItemOn` too; that part was
  never built.
- A chest hid this: the client's `useItemOn` does not see it as
  interactive (trace, VALIDATION-LOG 2026-11-01), only the server opens it.
  A door is toggled by the client itself.
- The SDK's only named writer is `setSneaking` (virtual, `Actor` and
  `LocalPlayer`), whose other effects are not known. `isSneaking()` reads
  `ActorFlags::Sneaking` in the player's `ActorDataFlagComponent`, a plain
  bit set that can be written alone.
- Built (`AsSent`, `SneakPlacement.cpp`): in "Send only", when Lamium
  edited the sent sneak bits and the local flag differs from the state
  sent, the bit is set to that state around the client's own `useItemOn`
  and put back after it; skipped unless `isSneaking()` reads the bit back.
  The first six uses log a line.

## Decided
- "Crouch briefly" does not become the default again: its cost is too high
  (maintainer 2026-11-26).
- A is tried first: the client's own use runs with the sneak flag set for
  that call and put back after it (the first plan), behind the capability.
  Where that cannot be done safely, B or a note in the method's help.

## Open
- Whether the client's `useItemOn` is where the door is toggled, or the
  decision is taken before it (then the flag must be set earlier, in
  `buildBlock`).
- B, if A fails: "Send only" falls back to the brief crouch for blocks the
  client toggles itself; which blocks those are (doors seen; trapdoors,
  gates, levers, buttons are guesses).
