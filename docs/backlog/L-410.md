# L-410 Sneak Placement "Send only" lets the client open a door the server keeps shut

Kind: Design (Bug)
Status: Cause confirmed in game (maintainer 2026-11-26); the fix to be chosen

With Sneak Placement on and the method "Send only" (the default), a right
click on a door with an item in hand opens it on the client only: walking
through pulls the player back as if it were shut. With a block in hand the
block is placed and the door still opens on the client.

## Known
- Seen in game (maintainer 2026-11-26, `15c6c182`): "Send only" with a spawn egg and with a block, the door
  opens on the client and not on the server; "Crouch briefly" with a spawn
  egg, the door stays shut on both.
- "Send only" puts the sneak bits on the sent auth input alone
  (`SneakPlacementSend`); the local player's own sneak flag stays off, so
  the client's `useItemOn` runs as an ordinary use while the server runs a
  sneaking one. The first plan of L-293 Place on interactive blocks as if
  sneaking had the client's flag set inside `useItemOn` too; that part was
  never built.
- A chest hid this: the client's `useItemOn` does not see it as
  interactive (trace, VALIDATION-LOG 2026-11-01), only the server opens it.
  A door is toggled by the client itself.
- Lamium never writes the player's sneak flag today. The SDK has
  `LocalPlayer::setSneaking` (virtual); what else it does is not known.

## Open
- The fix:
  - A: the client's own use runs with the sneak flag set for that call and
    put back after it (the first plan), behind the capability. To be
    tried: what `setSneaking` does besides the flag.
  - B: "Send only" falls back to the brief crouch for blocks the client
    toggles itself (doors, trapdoors, gates, levers, buttons).
  - C: "Crouch briefly" becomes the default again and "Send only" says in
    its help that doors and the like open on the client.
- Which other blocks the client toggles by itself (trapdoors, gates,
  levers, buttons are guesses).

## Next
The maintainer's choice of A to C; A starts with a read-only look at
`setSneaking` in a trace build.
