# L-410 Sneak Placement "Send only" lets the client open a door the server keeps shut

Kind: Research (Bug)
Status: Open; read in the code only, not reproduced on purpose (maintainer's report 2026-11-26)

With Sneak Placement on and a spawn egg (or a like item) in hand, a right
click on a door opens it on the client, but walking through pulls the
player back as if it were shut (maintainer 2026-11-26).

## Known
- "Send only" (the default method) puts the sneak bits on the sent auth
  input alone (`SneakPlacementSend`); the local player's own sneak flag
  stays off, so the client's `useItemOn` runs as an ordinary use while the
  server runs a sneaking one. The item's first plan had the client's flag
  set inside `useItemOn` too; that part was never built.
- A chest hid this: the client's `useItemOn` does not see it as
  interactive (trace, VALIDATION-LOG 2026-11-01), only the server opens it.
  A door is toggled by the client itself.
- "Crouch briefly" feeds real sneak input, so both sides agree; a door was
  checked with glass under that method (2026-11-01), not under "Send only".
- Lamium never writes the player's sneak flag today. The SDK has
  `LocalPlayer::setSneaking` (virtual); what else it does is not known.

## Open
- Whether "Crouch briefly" is free of it (expected), and whether a block in
  hand shows it too or the placed block makes the server send the door
  again.
- The fix:
  - A: the client's own use runs with the sneak flag set for that call and
    put back after it (the first plan), behind the capability.
  - B: "Send only" falls back to the brief crouch for blocks the client
    toggles itself (doors, trapdoors, gates, levers, buttons).
  - C: leave the method as it is and say so in its help.
- Which other blocks the client toggles by itself.

## Next
The maintainer tries the door with "Crouch briefly" and with a block in
hand; then a read-only trace of the client's and the server's result for
one use, before A is tried.
