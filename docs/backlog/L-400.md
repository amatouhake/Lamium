# L-400 The UI token check sees packed colors

Kind: Refactor
Status: Open

`scripts/Check-UiTokens.ps1` stops new `Rgb{...}` literals outside the
shared widget files, but a color written as a packed integer
(`packColor(242, 204, 61)`, `0xff5a64ffu`) or as the game's own color type
(`mce::Color{.25f, ...}`) passes. The check learns these forms; literals
that are a palette token under another spelling use the token.

## Decided
- The check counts the new forms per file in `UiTokenBaseline.txt`, like the
  ones it already counts: a file may not go over its count.
- A literal is replaced only where it is the same color with the same
  meaning as a token (a shape's color on the map is the shape's color). The
  replacement is proved equal at compile time.
- Map content keeps its own colors in the map's pure headers (radar dots,
  cave shading, the waypoint color choices, face outlines): they are data of
  the picture, not screen chrome. They stay counted.

## Open
- The schematic preview's check tints (`SchematicsView.cpp`: not placed
  `0xffffcc8c`, differs `0xff5a64ff`, state differs `0xff5ad7ff`) are a
  second set of values for the meanings `palette::notPlaced`, `mismatch`
  and `wrongState` carry. One set or two is a look choice.
- Literals equal to a token by value only: the minimap's unrecorded ground
  (`panel` at alpha 150) and the camera arrow (`accent`). Same meaning?
- `LockedTrades.cpp` and the HUD's own `slotCount` draw through the render
  context with their own colors instead of the shared widgets.

## Next
Extend the patterns and write the baseline; replace the shape colors; leave
the Open ones counted.
