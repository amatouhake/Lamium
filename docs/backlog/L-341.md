# L-341 Shared widgets for repeated controls

Kind: Refactor (strong model; no behavior change except where copies differ)
Status: Ready: palette tokens and the destructive button are in; next the plain and primary buttons

Screens carry their own copies of common controls. The 2026-11-14 review
counted: the press-twice confirm button (8; the danger red a literal in 7
files, HUD layout arming yellow instead), the text field frame (8), the
stepper (7 variants) and the scroll bar (5). Move each into
`src/ui/Widgets.h`, one at a time. The rules they must meet are in
DESIGN.md "Colors", "Controls" and "Screens"; not repeated here.
`scripts/Check-UiTokens.ps1` (baseline `scripts/UiTokenBaseline.txt`) only
lets the literal and hand-drawn button counts shrink.

## Decided
- Order: palette tokens, then buttons (plain, primary, destructive), the
  text field, the stepper, the scroll bar. For each control: list how the
  copies differ, agree, then write the DESIGN "Controls" entry and the
  shared widget in the same commit.
- Palette (built): the tokens in DESIGN "Colors". `info` is `.62,.83,1` for
  every reference blue; the schematic "wrong block" reds are `mismatch`;
  the near-yellows (hunger trace, schematic wrong state) are `warning`;
  black is `shade` with the opacity at the call; the schematic corner
  colors are `cornerOne`/`cornerTwo`; game-sampled colors and the preview's
  frame are in `palette::vanilla::`.
- Destructive button (built, `drawDangerButton` in ListViewWidgets): the
  same shape as the others. Unarmed it looks plain and turns red
  (`dangerEdge` `.85,.33,.3`, `dangerText`) only under the pointer, since
  an always visible red Reset in the settings header drew the eye; armed
  it keeps the red edge. Used by every delete/remove/reset button except
  the world map's own code (below), which follows the same colors.
- Game language gets the shared Open button; its row shows the current
  language faintly; Enter/Space on the row still opens the list.
- HUD layout (built): Done is a primary button, Reset a destructive one;
  the game's own HUD parts (frame, legend) are `info`.
- Focus loss: Game language follows Saved data and stays open (`calm()`
  instead of `reset()` in `cancelInputCapture`); every page that replaces
  the settings rows does the same.

## Open
Each a choice to agree when its control comes up, not a fix on sight:
- Esc while typing commits in the tool views but discards in the world map.
- "Add waypoint here" behaves three ways: prompt or not, camera or body
  position under FreeCamera, the temporary setting.
- The schematic save prompt's Save turns red while it would overwrite or
  is running (`SettingsScreen.cpp`): a primary button that becomes
  destructive, which the three kinds do not describe.

Left of the palette (not reference colors, no token yet): the calculator's
syntax colors, the world map's ground color, the waypoint distance text
(`.84,.86,.85`), the move target's gray, the switch/slider shades in
Widgets.cpp.
