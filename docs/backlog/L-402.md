# L-402 Check that every feature handles leaving the world, a dimension change and focus loss

Kind: Refactor **(strong model)**
Status: Open; the approach is not chosen

AGENTS.md rule 3 (restore vanilla when disabled, on world exit and
dimension change, and on focus loss for a feature that holds input or
changes game state) is kept by each feature on its own. Nothing in the
build or the tests can tell whether a new feature handles the four events.
No violation was found; this is about being able to check.

## Decided
- Features keep independent lifecycles (L-111 Integration between features).
- No general hook set (L-73 Architecture review, H).

## Open
- A: keep the per-feature handling and add a check. Each row of the feature
  table says which events it must handle ("holds input", "changes game
  state", "per world") and a test or script fails for a row that declares
  one and registers nothing for it.
- B: the feature table (`Runtime.cpp`) gets an optional `reset(reason)`
  beside `start` and `stop`, called from one exit listener, one dimension
  hook and one focus hook. Cost: the one hook is a shared point of failure,
  and whether a feature must act before or after the game's own handler
  differs per feature, so features move one at a time, each checked in game.
- With either: one world generation counter in `src/app` for stale
  background results, instead of one per feature.

## Known
- The feature table has `start` and `stop` only. Settings changes are
  pushed by name to four features in `Runtime::load` and `Runtime::save`
  (`configure`); `save` also resets Breaking Restriction and cancels
  repeated trades by name.
- 2026-11-24: 26 `ClientExitLevelEvent` listeners in 26 files (11 at the
  L-73 review), five hooks on `LevelRendererPlayer::$onWillChangeDimension`
  (Camera, Breaking Restriction, Periodic input, Permanent sneak, Fake
  offhand), three on `MinecraftGame::$onAppFocusLost` (Custom input, Camera,
  Hand restock).
- World and session generations are separate counters in the map store, the
  recipe service, item transfer, repeated trades and hand restock.
