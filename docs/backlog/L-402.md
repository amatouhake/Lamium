# L-402 Check that every feature handles leaving the world, a dimension change and focus loss

Kind: Refactor
Status: The table and its check are built (2026-11-26); three findings left for the maintainer

AGENTS.md rule 3 (restore vanilla when disabled, on world exit and
dimension change, and on focus loss for a feature that holds input or
changes game state) is kept by each feature on its own. The check makes
each feature write its answer down.

## Decided (maintainer 2026-11-26)
- Features keep independent lifecycles (L-111); no shared `reset(reason)`
  hook (L-73 review, H).
- [LIFECYCLE.md](../LIFECYCLE.md) has one line per feature row of
  `Runtime.cpp` (exit, dimension, focus: own, CustomInput, polled, n/a with
  why, or open); `scripts/Check-Lifecycle.ps1` (CI) fails on a missing or
  stray line. It proves the answer is written, not that the code does it.
- No shared world generation counter: only the recipe service and the
  minimap count worlds; the others count cancelled operations.

## Open
Read in code only (2026-11-26), none seen to go wrong in game:
- Sort, Death layout, Tool Protection and Auto Elytra keep moving items
  while the window is unfocused; Hand restock cancels on focus loss. Does
  an automatic item move count as "changes game state" for rule 3?
- Periodic input (Auto Attack/Use) keeps clicking while unfocused unless
  set to held-only: like a lock the player set, but rule 3 names only
  Permanent Sneak and Sprint.
- Sneak placement keeps `serverSneak`, `edited` and `heldAt` across a world
  exit and `stop()`: the next world's first input packet can carry a
  sneak bit from the old one.
