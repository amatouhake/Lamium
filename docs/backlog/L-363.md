# L-363 The game's tooltip and item details for a listed item

Kind: Research
Status: The tip is built and seen in game (2026-11-19); keys with data are built on branch `l363-data-keys`, not seen in game (2026-11-24); a food's hunger icons are left

An item Lamium lists (the item list, the favorites, the recipe view, the
plan) once showed only its name under the pointer: items that share a
name (potions, firework stars) could not be told apart, and Lamium's
item details did not show there (maintainer, 2026-11-18, after the first
check of [L-359](L-359.md)). The tip now says what the game says of the
item; what is left is the data a listed stack lacks and a food's icons.

## Decided
- The tip is Lamium's, in the game's tooltip box: the stack's own hover
  text, which Lamium's item details hook has added to, each line in the
  color it starts in, without the name and the lines of icon glyphs
  (`hoverLines`; RECIPES.md "The look"). Built and seen 2026-11-19.
- The item list keeps each creative entry with its data, every variant
  listed (each enchanted book's level); a fold only if that bothers
  (maintainer 2026-11-20, [L-371](done/L-371.md)).
- A key carries the data that makes the item what it is, as SNBT after
  the name and aux, not all of its data: a carried stack has to meet the
  creative entry though use may add data (a name, an anvil's repair
  cost). JEI's public wiki describes the same split (a plugin says what
  makes an item unique: a backpack's color, not its contents). Tried on
  a branch first, since the risk is not known (maintainer 2026-11-24).

## Known (read in code 2026-11-23)
- The list is read from `CreativeItemRegistry::mCreativeItems`
  (`readNames`, `ItemList.cpp`), whose entries' `mItemInstance` carry
  their data: English search finds a creative enchanted book by its
  stored enchantments (L-344, seen in game).
- Each entry is kept by its key (`ItemKey.h`, `StackKey.cpp`), and a
  second entry with the same key is dropped. Potions, firework stars,
  beds and banners differ by aux.
- Counted in game (`recipe_trace`'s `creative-*.txt`, VALIDATION-LOG
  2026-11-24): 1980 entries, 1839 keys. Only three keys fold, 141 entries
  left out, none a copy: 125 enchanted books (`ench`: one enchantment and
  level each), 17 firework rockets (`Fireworks`: none or one dye color's
  explosion) and the ominous banner (`banner@15` with `Type:1`, lost
  behind the white banner). Rocket recipes give `firework_rocket:0`.
- On the branch: books carry `ench`, rockets `Fireworks`, banners a
  nonzero `Type` (`identityTags`); every other key is as before. Applied
  to the dump offline: 1980 entries, 1980 keys, 143 keys changed. The
  icon and tip are drawn from a stack rebuilt from the key with that data
  as its user data (`shown`, `SchematicItems.cpp`); `readNames` logs how
  many keys do not come back from their stack.
- The same keys are what favorites, wanted items, the plan and the recipe
  index name items by; favorites are saved as keys in the recipe notes
  file (`RecipeNotesStore.cpp`).
- The hunger icons in item tooltips are Lamium's Food values (L-92), not
  the game's: the hover text hook adds a line of U+E0FF placeholders,
  and `TooltipPainter` draws the icons over that line in the game's
  tooltip (`drawFoodIcons`, `information::saturation::foodIcons`;
  ITEM-DETAILS.md "Food values"). `hoverLines` drops that line as icon
  glyphs, so Lamium's tip has no room and no icons.

## Open
- Whether carried books and rockets key as their creative entries (one
  from an enchanting table or anvil, a crafted rocket): not seen.
- Not data-aware: the plan, "can be made", counting what is carried and
  stored for a wanted item, the schematic Materials tab (RECIPES.md
  "Limits"). Favorites saved by a main build as a bare book still load
  and show as a plain book. Whether to merge is decided after the check.
- Recipes see the base item: the ominous banner shows, plans and lays
  the white banner's recipe and counts as "can be made" with it; every
  rocket is "can be made" once one is. Books have no recipe. Whether a
  key with data should keep its base's recipes is to be agreed.
- Not built: kinds outside `identityTags` (a server's or add-on's items
  that differ by data alone) still fold to one entry.
- Food icons: the tip could keep the placeholder line as a blank line
  and draw the Food values icons over it with the same helper, following
  the Food values setting. Not tried; the icons are images, which
  Lamium's tips have not drawn so far.
