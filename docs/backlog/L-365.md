# L-365 The world behind a server, Realm or friend's world can change

Kind: Ready (Bug: GitHub issue #82) (strong model)
Status: Built; every question and answer checked on a local BDS (2026-11-19); a Realm not seen

A data set is named by who was joined: a server's address, a Realm's id
(L-358), a friend's world's level id. The world behind it can change (a
Realm's slots, a server's reset, a copy of a world put in a Realm's slot
for creative) and Lamium kept writing the new world into the old world's
data. Nothing tells a copy from the same world changed for certain, so
Lamium matches what it can and asks the player once when they differ.

## Decided
- A world's print at join: seed (`Level::getLevelSeed64`, 0 when hidden),
  world name, default game mode and hardcore.
- Each data set of one identity remembers the prints it was used with. A
  join whose print matches one uses that data without a word: going back
  and forth between a Realm's slots needs no question.
- A print not seen before is decided for now and asked: both seeds known
  and different starts new data (`<key>-w<n>`); otherwise the data last
  used goes on, a data set with this seed first.
- The question is the docked notice of the tool screens (map, waypoints,
  placements, shapes), ahead of the fuller-data notice, until answered:
  new data started: Keep new data / Use the saved data / Do not split here;
  data kept: Start new data / Keep this data / Do not split here. The
  answer is remembered for the print. A join that asks also shows a toast
  pointing to the screens.
- "Do not split here": this identity always uses one data set, its base.
  The Saved data page says so on that data and offers "Split worlds
  again" (its own row above the other buttons), which asks again from the
  next join (maintainer 2026-11-19).
- Data from before this has no print: the first join adopts its print, so
  updating Lamium neither asks nor splits anything.
- The same for servers, Realms and friends' worlds; the player decides per
  identity.
- A server whose swapped world brings another level id is a new server
  already (L-343) and gets the fuller-data notice, not this question.
- A server with several data sets names each, in the list and the notice,
  "<address> - <world>" by the world it was last confirmed with
  (maintainer 2026-11-19).
- Pure: `map/WorldPrints.h`, `servers::dataName`, tested in WaypointTests.cpp.
