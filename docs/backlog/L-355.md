# L-355 Color tokens for the schematic check's wrong state and not placed

Kind: Design (small)
Status: Open; waits for the maintainer's choice of colors

`mismatchColor` in `SchematicsView.cpp` colors the Check list's kind
squares. Wrong block and extra use `palette::mismatch` since `7f27f919`;
the other two are still color literals, which rule 7 (AGENTS.md) forbids:
wrong state `{1, .8, .25}` (yellow) and the default, not placed,
`{.75, .85, .9}` (pale blue). `Check-UiTokens.ps1` does not see them: its
pattern looks for `Rgb{`.

## Known
- No palette token has either value. `palette::warning` and `palette::info`
  are near but not equal, so using them changes what the player sees.
- The in-world marks use the same three meanings with their own values
  (`GhostMesh.cpp`, the yellow mark is `1, .8, .2`).

## Open
- Two new tokens with today's values (for example `palette::wrongState`
  and `palette::notPlaced`), or the existing `warning` / `info` with the
  small change of color.
- Whether the list's squares and the in-world marks share the tokens.
- Whether `Check-UiTokens.ps1` should also catch a returned brace list.
