# L-357 HUD elements: their size and their text size apart

Kind: Design
Status: Demo made 2026-11-17; waiting for the maintainer's choice of model

An element's one scale (HUD layout editor, 50-200 %) sizes everything in it:
graphics and text together. So an element cannot be large with small text.
The minimap is where it showed first: its size moved into the editor alone,
which made its text large, and a separate "Text size" (`map.textSize`) was
added that multiplies with the scale, so the text still changes with the
map's size. The maintainer: handle it for the HUD as a whole, the map being
the first case, not a special one (2026-11-17).

## Decided
- One answer for every Lamium HUD element and the HUD layout editor; the
  minimap's text size is folded into it, not kept as its own rule.

## Open
- The model. Candidates:
  1. Each element has "Size" (map, icons, bars, slots) and "Text" in the
     editor's toolbar; text no longer follows Size. A text-only element has
     Text alone.
  2. One HUD-wide text size; an element's scale no longer touches its text.
  3. As 1, with a "text follows size" switch per element (on: as today).
- Which elements have both (minimap, inventory grid, durability, status
  effects, player list, offhand slot, ...) and how each lays out text that
  sits on or beside graphics (a slot's count in its corner, a number beside
  a bar) when the two differ.
- Moving saved layouts so each element keeps today's look, and what becomes
  of `map.textSize` (a settings format change: agree before building).
- The game's own HUD parts (position and scale only today).
