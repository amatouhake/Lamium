# L-357 HUD elements: their size and their text size apart

Kind: Ready (strong model)
Status: Decided 2026-11-17; the inventory grid's slot size is built, the Look popover is not

An element's one scale (HUD layout editor, 50-200 %) sizes everything in it:
graphics and text together. So an element cannot be large with small text.
The minimap is where it showed first: its size moved into the editor alone,
which made its text large, and a separate "Text size" (`map.textSize`) was
added that multiplies with the scale, so the text still changes with the
map's size. The maintainer: handle it for the HUD as a whole, the map being
the first case, not a special one (2026-11-17).

## Decided
- One answer for every Lamium HUD element and the HUD layout editor; the
  minimap's text size is folded into it, not kept as its own rule.
- Maintainer 2026-11-17: per element a two-way choice, text at the standard
  size (as at 100 %, ignoring the element's scale) or following the scale.
  No per-element text sizes; a text size, if ever wanted, is one
  Lamium-wide setting (the game's GUI scale already sizes everything).
- Elements with the choice (graphics beside their text): minimap,
  durability, status effects, target, schematic HUD, player list.
  Text-only elements (info lines, status, toast, magnification, used slots)
  keep their scale as their text. Text on graphics (a slot's count) follows
  the scale.
- Toolbar: background, shadow and this choice go into one "Look" popover,
  as Contents is one (every Lamium-drawn element has background and shadow;
  the game's own parts keep position and scale only). The toolbar becomes
  snap, scale, Look, [Contents], Reset.
- Defaults: saved layouts keep following the scale (nothing changes); new
  installs start at the standard size for the elements above.
- `map.textSize` goes; the minimap takes the choice instead.
- The inventory grid's slot is the hotbar's 20 units at 100 % (was 18),
  so matching the hotbar no longer enlarges the counts past the game's;
  a saved scale is converted once (x 0.9, `cell` marks a converted entry).
  Built 2026-11-17.
