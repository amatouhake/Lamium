# L-338 When a death layout ends

Kind: Feature
Status: Built 2026-11-14 on the maintainer's go-ahead, not checked in game

A death layout also ends once its dropped items must be gone, so a stale
layout does not restore long after the death.

## Decided
- Rule (DESIGN.md, L-338): the layout ends once the place of the death has
  been loaded around the player for 5 minutes in total. "Loaded" is the
  death's dimension and 48 blocks across (inside the smallest simulation
  distance, so the count never runs ahead of the items); away from it the
  count stands still.
- The count is kept in the layout file (`loadedTicks`, saved every 10 s),
  runs with the feature switched off too, and waits while a restore is
  moving items. Ending shows "Death layout restore ended: the dropped items
  are gone by now"; the help text explains the limit. Pure part: `age`,
  `loadedAround` in `DeathLayout.h`, tested.
- Accepted for now: on a server other players can keep the chunk loaded
  while this player is away, so the items can be gone with the count
  unfinished; the layout then ends at the next death. No second, long limit.
- Unchanged: a started layout is still dropped on the first tick after
  joining more than 32 blocks away (the L-332 rule).

## Next

file removed); go far away and return later (still restores); rejoin in
