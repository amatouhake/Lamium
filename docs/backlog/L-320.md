# L-320 Highlight designated block types in the world

Kind: Design
Status: Released in 0.6.0 (Experimental); open are in-game checks and any follow-ups the maintainer raises

The player designates block types (diamond ore, ancient debris, anything)
and they glow in the world so they are not overlooked, far away or in the
dark. Bedrock cannot switch resource packs inside a world, so this is a
client feature. Maintainer's idea 2026-11-07.

## Decided
- No scan: the tessellator hook records each designated block's drawn faces
  per chunk section (`RenderChunkBuilder::build`; both
  `tessellateBlockInWorld` and the shape dispatcher `tessellateInWorld`),
  and the world overlay draws them unlit with an outline. Reach is the
  render distance; changing the list or the switch rebuilds chunks once.
  Data comes only from chunks the client has received, never the map record.
- Recorded faces are those not covered by an opaque full block. A non-cube
  block glows as its full cell; blocks that add no vertices (chests, shulker
  boxes) are marked by their uncovered faces. Blocks buried on every side
  never show.
- Matching by block name only (states ignored; deepslate ores are their own
  names). The list is global (settings), not per world, and stays until
  removed; no expiry.
- Key: adds the aimed block's type, or removes it if listed. While Freelook
  or FreeCamera owns the view it takes the block the target card picks
  along the camera's ray; from the body, the game's own hit.
- List screen (mockup A): an action row under Block highlight with the
  usual Open button (its key unbound by default) replaces the settings rows
  like the game-language list. Left: listed types in order added (icon,
  name, ID, "nearby" count, two-press remove). Right: search over every
  registered block type by display name and ID, listed ones marked, click
  adds or removes. Needs a world (icons). The footer says chests and the
  like are not covered. Nearby = recorded marks of that type. Suggestions
  include the wet sponge after the ores. No deepslate sibling offer (removed
  2026-11-11: it moved results under the pointer). Target card shows
  "Highlight: listed".
- Look (maintainer 2026-11-09): "Color" row Rainbow (default, flowing and
  pulsing; hue from time and position, same for every type) / Cyan /
  Yellow / Pink / White (Shapes palette); a single color is still, no pulse.
  "Strength" 0-100 % step 5, default 50 %; 100 % about doubles the faces, 0 %
  leaves edges only. No speed, edge, pulse or separate through-walls
  controls. Does not follow the Animations setting; a still color stops
  motion. No mesh tint: the texture stays vanilla. Saved per-type colors
  stay in the file unused; the list offers no recoloring.
- Through walls (maintainer 2026-11-09): an option, off by default, also
  draws recorded faces behind terrain, faint and without edges; each vertex
  is moved along its ray to about two blocks from the eye (no material
  without depth test is known). Main switch and Through walls both default
  off (Experimental; servers may see Through walls as X-ray).
- Cost: rainbow refreshes faces in batches of 1024 at `rainbowRefreshHz` = 20
  (maintainer kept 20 after the 2026-11-09 check); a still color rebuilds
  meshes only when faces, color, strength or material change; through-walls
  faces rebuild when the camera moves. Face cap `maxGlowFaces`; a capped
  list is rechosen after moving 8 blocks.
- A schematic placement's blocks do not share this list (maintainer
  2026-11-08).

## Tried
- Mesh tint with UV1 raised as full light: UV1's scale is not 0..1 (read
  ~0 in a dark cave), the block got darker, and Night Vision washed the tint
  out. Replaced by the glow overlay.
- A scanned overlay (radius 64): too short for far blocks.
