# L-351 One wording for press-again confirmations

Kind: Ready
Status: Reworked, not checked in game

The two-press buttons shared the danger button's look but worded the armed
state four ways ("Press again to delete", "Press again", "Again",
"Delete N?"; Japanese also mixed 削除 / 消す and one polite 戻します).

## Decided
Maintainer 2026-11-15 (after checking the "Again: " build):
- An armed button says what the second press does: "Confirm " + the
  action ("Confirm delete", 「削除を確定」, 「确认删除」, 「確認刪除」), one
  whole string per action that reads naturally, built once in the shared
  widgets so no screen words it by hand.
- A button too narrow for that reads just "Confirm" / 「確定」 / 「确认」 /
  「確認」.
- A bulk delete names its count in the button ("Confirm delete 5",
  「5 件の削除を確定」), a stated exception to "counts go beside the button".
- A two-press button sized by its text is as wide as the longer of its
  two labels from the start, so arming moves nothing (the HUD editor's
  Reset layout and its panel included).
- Saved data shows nothing beside Delete: the details above already give
  the waypoint count and map size.
- Things the player made or saved (waypoints, shapes, placements, saved
  data, the map cache) are "Delete" / 削除, not 消す; no polite forms.
- The rule is in DESIGN.md ("Buttons").

## Built
`armedLabel(context, label, confirm, armed, width)` in ListViewWidgets.h
picks the confirm text, or `confirm.short` where it would be cut in the
button (pure choice `armedText` in TextFit.h, tested); `armedWidth` sizes a
text-sized button for both labels; `confirmDelete(count)` gives
`confirm.delete` or `confirm.deleteCount`. Used at every press-twice
button:

| Button | English armed | Japanese armed |
| --- | --- | --- |
| Waypoints / Shapes / Schematics Delete, world map Delete and its menu item, map cache Delete, Saved data Delete | Confirm delete | 削除を確定 |
| Settings table Reset (all, category, all keys) | Confirm reset | 初期化を確定 |
| HUD editor Reset layout | Confirm reset | リセットを確定 |
| Schematic check Undo all | Confirm undo all | 取り消しを確定 |
| Highlight list Remove (40 units) | Confirm | 確定 |

Stable width (`armedWidth`): the HUD editor's Reset layout, Saved data
Delete, the map cache Delete, Undo all and the world map panel's Delete.
The others have fixed widths and fall back to "Confirm" if cut.

Choices made without asking:
- Wordings per action: the HUD editor's 「すべて既定に戻す」 arms as
  「リセットを確定」 and Undo all's 「すべて戻す」 as 「取り消しを確定」 (their
  labels + を確定 read badly); zh "确认重置布局" / "確認重設版面配置" and
  "确认全部撤销" / "確認全部復原"; the count form is 「{} 件の削除を確定」,
  "确认删除 {} 项", "確認刪除 {} 項".
- The highlight list's Remove always passes the short form as its confirm
  text: nothing longer fits 40 units.
- The world map's context menu item has no width to fit (the menu sizes
  itself), so it always shows the full text.
- The large schematic file's Load stays as it is: a warning above a plain
  Load button, nothing destructive.
- The schematic save prompt's Overwrite stays as it is: its armed state is
  a different control (a new label with the reason in the prompt), not a
  press-again button.

Not measured in game: whether "Confirm" fits the highlight list's Remove
(40 units), and whether "Confirm reset" / 「初期化を確定」 fit the settings
table's Reset (84 units) or fall back to the short form.
