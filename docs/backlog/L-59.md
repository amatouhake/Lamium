# L-59 Held placement style: vanilla, Java-like or fast

Kind: Design done; Research first, then Ready **(strong model)**
Status: Planned, nothing built; no step starts until the maintainer says so

Build bridges and long straight lines quickly by holding the use button
with a block. Block placement only; eating, bows and buckets keep vanilla
behavior. (Started as "keep placing across a left click" after L-49 closed
as vanilla parity.)

## Decided
Maintainer 2026-09-28:
- One setting, "Held placement", under Actions: Vanilla (default, since
  Bedrock players would be surprised otherwise), Java-like, Fast.
- Vanilla: Bedrock's own held build session, unchanged.
- Java-like: while use is held with a block, place on whatever face the
  crosshair targets every 4 ticks; no direction lock, no placing into air,
  nothing when no face is targeted. An intervening left click does not end
  it: placing resumes while right is still held.
- Fast: while right is held, place on each new block face the crosshair
  crosses, capped per tick (a setting, modest default). Help text warns some
  servers may treat it as unfair. Also survives a left click.
- Both non-vanilla styles respect the placement restriction (L-15) when it
  is on, which turns Fast into "paint a flat floor".
- Interactive blocks (chests, doors, buttons), ordinary attacks, Fake
  Offhand and custom activation chords keep their current behavior.

## Open
Hypotheses about Bedrock's held build session, not facts until traced
(sources: Java mods describing Bedrock, behavior only:
modrinth.com/mod/pro-placer, github.com/squeeglii/BridgingMod/issues/13):
the first placement locks a build direction; hovered blocks outside it are
ignored; it may place into air ahead of the last block while bridging; it
may place as soon as a position is valid instead of on an interval.

## Next
1. Research: record the held build session with the L-49 trace
   (`research_trace`, `FakeOffhandTrace.cpp`) and confirm or correct each
   hypothesis: what sets the direction lock and which positions it accepts,
   placing into air, timing, what ends the session. Test whether one
   discrete ordinary build action through the existing
   `GameMode::buildBlock` / `SurvivalMode::buildBlock` hooks is enough for
   one server-authoritative placement, and map any start/stop lifecycle.
   Do not synthesize a custom packet to imitate held input. Report before
   building.
2. Java-like style, with tests for the interval and the left-click rule.
3. Fast style with the per-tick cap; then combine both with L-15's placement
   restriction once that exists.
