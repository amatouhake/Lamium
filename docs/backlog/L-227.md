# L-227 FreeCamera outside the loaded area shows only the sky

Kind: Bug / Research
Status: Waiting for the maintainer: whether it is worth two read-only trace rounds

With FreeCamera flown about one chunk past the edge of the loaded area, all
terrain disappears at once, also the loaded terrain still well inside the
camera's render radius; only sky and environment draw (maintainer
2026-10-19, `9a565f0`). So something keyed to the camera's own position
having no chunk, not the render radius. Terrain beyond the loaded area
stays out of scope ([CAMERA.md](../CAMERA.md)).

## Decided
- Any new path is a game dependency (GAME-UPDATES.md) and needs the
  maintainer's go-ahead.

## Open
- Whether this is worth two trace rounds: flying past the loaded area is
  rare. A cheaper alternative with no game dependency is a product choice,
  not decided: stop the camera at the loaded edge, or show a notice when it
  leaves.
- Hypothesis (not confirmed): the visibility walk starts at the camera's
  render chunk; a render chunk with no level chunk has no visibility data,
  so the walk ends at once. Matches "one chunk past, all at once" and both
  culler types failing.

## Next
Each step a read-only trace build, after the go-ahead:
1. In the `TerrainPreRender` hook, once per second while FreeCamera is on,
   log `mCameraPos`, `mViewAreaDistance`, `mViewAreaSide`,
   `mLastCullerType`, `mForceCulling`, `mShowSky`, whether
   `getRenderChunkInstancedAtShared` at the camera's and the player's
   sub-chunk is non-null, and `cullerIsVisible(playerPos, 8)`; compare one
   chunk inside and outside the edge. Separates "view area lost the loaded
   chunks", "culler rejects them", "pass the culler but not queued".
2. Map culler type numbers to kinds: request 0..7 for one second each in a
   flat world and log `mLevelCuller`'s class name from its vtable RTTI.
3. If 1 shows the culler rejecting loaded chunks and 2 finds a None kind,
   request None (via the L-37 hook) while the camera's column has no chunk,
   behind `versionSensitiveAllowed`, watching frame time (None draws every
   loaded chunk).

## Tried
- The L-207 culler gate: with the underground hold on Always (spectator
  culler all session) the sky-only view stays. Outside the loaded area the
  hook's `inside` test is false, so the choice is 3, or 5 with Always; both
  fail.
- Splitting the culler's start from the view: FreeCamera moves the camera
  through `CameraAPI::$tryGetActorInterpolatedPosition` and `setupCamera`,
  so both get the same position at those hooks.

## Known (SDK 26.60.4 headers)
- Culler classes are empty; `LevelCullerType` has no names (only 3 and 5
  known). Kinds that exist: None, NoneAsync, Manhattan, CachedStep,
  DistanceField (Perspective/Orthographic), Shadow.
- `shouldCullThisFrame` and any "culling point" are not in the 26.60.4
  headers, so "keep the culling point at the nearest loaded chunk" has no
  symbol to start from.
- `LevelRendererCamera` has `mViewArea`, `updateViewArea`/`setViewArea`,
  `mViewAreaDistance`, `mViewAreaSide`/`mViewAreaHeight`/`mViewAreaChanged`,
  `mViewRegion`, `mCameraPos`, `mCameraTargetPos`, `mLastCameraPos`,
  `mForceCulling`, `mRecullWhenNotBusy`, `mShowSky`, `_createCuller`, and
  read-only `cullerIsVisible(point, radius)`, `isAABBVisible(aabb, fast)`,
  `getRenderChunkInstancedAtShared(SubChunkPos)`.
