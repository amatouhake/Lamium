# L-324 Map: custom blocks are drawn in a dirt-like brown

Kind: Ready (strong model; cause unconfirmed, fix rule agreed)
Status: Built, not checked in game

On the minimap and world map, add-on blocks show brown instead of their own
color, while the game's map item shows the color of their
`minecraft:map_color` component (issue #76, reported on 0.6.0, game 26.60,
with steps: an add-on with such blocks, a filled area, compare with a map
item).

## Decided
- Rule (maintainer 2026-11-15, replacing the earlier "add-on map color
  first"): every block, vanilla or add-on, is drawn by its look first (the
  top texture's average); `getMapColor` only when no look is found, which
  includes a top texture of `textures/blocks/missing_tile` or an image that
  cannot be read. An add-on block's texture comes from its
  `minecraft:material_instances` when `BlockGraphics` has none. The
  map-color-first path goes.
- Test packs (`tests/packs/map-color`): four blocks, A cyan texture +
  magenta map_color, B yellow texture, C/D missing texture with/without
  magenta map_color. Dirt brown means the look was not found.

## Built
- `blockLook` (`Minimap.cpp`): the `BlockGraphics` top texture as before;
  the missing texture path counts as no look, is not loaded and costs no
  texture load. Then, for an add-on block (outside `minecraft:`), the
  material instance for "up", else "*" (`topMaterial`): its `mTextureName`
  (a `terrain_texture.json` key) resolved with
  `BlockGraphics::getTextureUVCoordinateSet` and averaged like any texture,
  with the instance's tint when it has one. `getMapColor` when neither gives
  a color. Cached per state; texture colors per path. Rule in `MapColors.h`
  (`knownTexture`, `topFaceRank`, `lookSource`), tested.
- `Block::tryGetComponent<BlockMaterialInstancesComponent>` does not link
  (not in the symbol data). The component is found as that template does:
  the game's `type_id<void, BlockMaterialInstancesComponent>` static,
  resolved by name with `SymbolView` (an import reads a delay-load stub),
  then `_findComponentBase` on the state, else the type; log says which.
- Capability "Map colors of add-on blocks (block material instances)" gates
  that read (agent's choice): walking a game `unordered_map` and string by
  SDK layout, reached by a mangled-name id, crashes rather than fails open
  if the layout moves, which is what AGENTS.md rule 8 gates. Off, add-on
  blocks with a missing texture take the game's map color. Vanilla blocks
  never read it. The map color component read and its rule
  (`usesDefinedMapColor`) are gone.
- The diagnostics log names the first 8 add-on blocks: `BlockGraphics`
  texture, material instance texture name and resolved path, image yes/no,
  color and which path (texture, material instance, map color).
- Saved tiles keep their colors until scanned again (`columnRevision` kept).
- Test packs rebuilt by `tests/packs/map-color/tools/make_packs.py` (2.0.0,
  new UUIDs), installed on the Dev instance; the old packs' test world now
  lists the new ones.

## Known/Tried
- `MissingTextureAtlasItem::missingTextureItem()` and `getDefaultTextureName`
  do not link (`MCNAPI`): the missing texture is recognised by its path.
- Not checked: what `getTextureUVCoordinateSet` returns for a name missing
  from the atlas (C and D test it; an empty path or the missing texture both
  count as no look).
- The first test packs' textures did not load. Most likely cause:
  `minecraft:material_instances` without `minecraft:geometry`, so the game
  used `blocks.json`, which the pack lacks (that is also why `BlockGraphics`
  gave `missing_tile`). The new blocks carry `minecraft:geometry.full_block`;
  with it `BlockGraphics` may still give `missing_tile`, which is the path
  the material instance read covers.

## Seen (2026-11-15, `156daadf`, first test packs)
- Both blocks showed the missing texture in the world; the log named their
  top texture `textures/blocks/missing_tile`; the map-color block drew its
  map color, the other brown. Maintainer: why should add-ons prefer the map
  color over their look? (Now the rule.)
