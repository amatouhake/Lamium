# L-393 Target card icon loses the item's data (glint, dye, modded icons)

Kind: Ready (Bug)
Status: Built, not checked in game (item frames and dropped items, 2026-11-23)

The target card's main icon for an item frame's contents or a dropped item
is rebuilt from the item's name and aux only, so what the item's data draws
is lost: an enchanted item's glint, dyed leather, a loaded crossbow, armor
trims, and items of client mods that pick their icon from the stack's data. The card's detail
rows and the container previews keep the data and draw these correctly.

## Decided
- `TargetIcon` (`TargetInfo.h`) carries the stack's binary NBT, as
  `TargetInfo::DetailRow::icon` and `TargetCard.h`'s row icon already do;
  empty when the icon does not come from a real stack.
- `TargetInfo.cpp` fills it (`ItemStackBase::save`, binary NBT, Count set
  to 1 so a pile that merges keeps one decoded stack in `schematic::items`'
  cache) for two targets:
  - an item frame or glow item frame: `blockIcon` already shows the item the
    frame picks (`asItemInstance` with data), and keeps that item's data;
  - a dropped item (`droppedIcon`). The game's own pick never names one, so
    it is the target only through Lamium's pick: FreeCamera, Freelook, or
    nothing in the game's reach.
- Other blocks keep name and aux (maintainer, 2026-11-23): their picked data
  is their contents (a chest's items), which an icon does not show, and a
  banner's or head's look was not checked.
- The target is looked up several times a frame, so the data is saved at
  most every 250 ms per target, as the block entity rows are. Each distinct
  item looked at stays in that shared cache until world exit (16384 cap).
- No `GAME-UPDATES.md` entry: `ItemStackBase::save` is a plain call, not a
  hook, like `ItemStack::fromTag` beside it.
- `iconStack` (`InfoHud.cpp`) draws the stack `schematic::items::iconStack`
  decodes from that data, as the rows do, and falls back to name and aux
  when there is none or the cache is full; the pickup flags stay cleared.
- The snapshot holds no game pointers (AGENTS rule 2).
