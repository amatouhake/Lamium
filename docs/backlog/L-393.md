# L-393 Target card icon loses the item's data (glint, dye, modded icons)

Kind: Ready (Bug)
Status: Reported on GitHub (issue 83, 2026-11-23); not started

The target card's main icon for a dropped item is rebuilt from the item's
name and aux only, so what the item's data draws is lost: an enchanted
item's glint, dyed leather, a loaded crossbow, armor trims, and items of
client mods that pick their icon from the stack's data. The card's detail
rows and the container previews keep the data and draw these correctly.

## Decided
- `TargetIcon` (`TargetInfo.h`) carries the stack's binary NBT, as
  `TargetInfo::DetailRow::icon` and `TargetCard.h`'s row icon already do;
  empty when the icon does not come from a real stack.
- `droppedIcon` (`TargetInfo.cpp`) fills it from the item actor's stack,
  with the same serialization the detail rows use. Any other place that
  builds the card icon from a real stack does the same.
- `iconStack` (`InfoHud.cpp`) rebuilds the stack from that data when it is
  present (as `schematic::items::iconStack` does for the rows) and falls
  back to name and aux; the pickup flags stay cleared.
- The snapshot holds no game pointers (AGENTS rule 2).
