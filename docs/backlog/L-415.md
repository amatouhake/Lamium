# L-415 Mouse bindings act while a field is typed

Kind: Ready (Bug)
Status: Open, not started (from L-390's questions 5 and 2, 2026-11-28)

SETTINGS-KEYMAP.md "Where actions work" says no binding acts while the
player types (the search field or a count). A binding on a mouse button
still acts then: the mouse listener in `input/CustomInput.cpp` (about line
215 at `69271bd2`) does not ask whether a field is being typed, as the key
listener does.

## Decided
- The keymap document is the contract: while a field is typed, a mouse
  button binding does nothing, as a key binding does. Plain clicks on the
  screen keep working.
- Also read MASS-CRAFT.md against `finish()`: the review found the docs
  saying that releasing the Mass Craft key puts the pointer back and throws
  the product, while `finish()` makes no game call and the tidying happens
  at the next step's start. Make the document say what the code does.

## Next
Add the typing check to the mouse path, with a pure test if the decision
can be lifted out; fix the Mass Craft wording.
