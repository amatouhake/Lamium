# L-358 Realms joined through a friend share one data set

Kind: Research (Bug: GitHub issue #81)
Status: Open; waiting for an answer on which Realm identifier is stable, and for a friend's-world check

A Realm joined through a friend comes without an address, so its data goes
by the level id alone (the `world_` key of L-343). Two Realms of one friend
reported the same level id, so the second wrote into the first's data and
the map mixed both (user report on Discord, 2026-11-17; the join log line
"joined without an address; its data goes by the level id" showed the same
id for both). Data already mixed cannot be separated.

## Known
- SDK 26.60.4 holds three Realm identifiers: `GameConnectionInfo::mNetherNetId`
  as `NetherNet::Realms::NetworkID` (a UUID; L-343's trace build logs it,
  `WaypointSession.cpp` `traceIdentity`), `Realms::RealmId` in
  `MinecraftGame`'s reconnect cookie, and `FriendWorld::mRealmId` (an
  optional string in the friends list facet). Whether the NetworkID is fixed
  per Realm or changes per connection is not documented anywhere found.
- A friend's own world takes the same path; whether two of a friend's
  worlds can report one level id is unchecked. The shipped log line above
  answers it without a special build.
- Nobody at hand owns a Realm, and asking the reporter to run an unreleased
  DLL was ruled out (maintainer 2026-11-17).

## Open
- Which identifier is stable per Realm: asked on the LeviMC Discord.
- Whether to also log the NetherNet id's kind and a short hash at join, so a
  friend's-world check can see whether it changes per world or per session.

## Next
1. Fallback that needs no Realm: a no-address join whose world name or seed
   differs from the data's stored ones starts new data instead of writing
   into it; the key choice pure and tested. Two Realms with the same name and
   seed would still share.
2. A friend hosts two worlds in turn; compare the join log's level ids.
3. With an answer on the identifier: key Realms by it, the old `world_` data
   reachable with "Use this data".
