# L-190 Select several rows at once in list screens

Kind: Ready (strong model)
Status: Selection pane seen in game 2026-11-15 (`00d4be5f`); follow-ups agreed, not built

In list screens select several rows and act on them together (for example
show, hide, delete). Maintainer idea 2026-10-14.

## Decided
Maintainer 2026-11-06 and 2026-11-15:
- Lamium does not say it supports multiple selection until the lists that
  need it have it: Shapes, schematic placements, the map's side panel and the
  Schematics Check list (for L-183). Merge and announce together, so
  FEATURES.md and the README stay silent until then. No file format change.
- Every list: Ctrl + click toggles a row, Shift + click takes a range; no
  drag selection; Ctrl + A selects all; a plain click selects just that row.
  All selected rows have the same highlight; no row is kept as primary.
- Two or more rows: the right detail pane becomes a selection pane; no bar
  in or under the list anywhere. A header with the count ("5 selected");
  the selected names in list order with their color mark as plain lines, as
  many as fit, the last reading "N more" when they do not. The bulk actions
  sit where the single pane's buttons sit (same row, size, spacing), Delete
  in the single pane's Delete place ("Delete N?" on the first press).
- Esc with several rows clears the selection (the pane's empty state), the
  next Esc closes as before.
- Bulk actions: Waypoints, Shapes and schematic placements show, hide,
  delete (no bulk move or turn); the map side panel show and hide only,
  with the count where its single selection's details go, no names, and the
  list keeping its height.
- The Check list (ignore as one block, un-ignore, show in world) comes after
  L-183's mockup settles how ignored rows look.

Maintainer 2026-11-15, after the check:
- The selection pane's name lines carry the same extra the list row shows
  (distance, progress), under a summary line ("Shown N / Hidden M").
- Lists share one column shape: mark (kind and color), name, distance,
  the list's own column (placements: progress only), shown. Shapes' type
  goes into the mark; positions move to the detail pane.
- The map side panel matches the others: Delete (two presses) and names as
  space allows.
- On the map, Ctrl + click on a mark adds it to or drops it from the
  selection (no range, no box selection).
- Open: the armed Delete wording ("Delete N?" is unlike the others).

## Built
Shared: `ui/RowSelection.h` (selection, `single()`, Esc clearing, names-fit
and button layout, actions per list; tests in `tests/RowSelectionTests.cpp`),
`ShapesLayout::selecting` and `selectionPane()` (hits in
`tests/ShapeEditorTests.cpp`), `drawSelectionPane` in `ListViewWidgets.h`.
Waypoints, Shapes, the Placed tab (in and out of docked) and the map's side
panel use them.

Chosen without asking (least surprising):
- On a narrow pane (under 228 units) Show and Hide narrow so they stay clear
  of Delete, which keeps its place and width.
- The names' mark is each list's own glyph (diamond or cross, shape type
  icon, dimmed when hidden or elsewhere); placements have none, so their
  names stand alone. Names in another dimension are faint.
- The footer says "N selected" while several rows are selected.
- Placed tab: several rows pick no placement; the schematic's selected one
  (its accent bar, keys, HUD, Check tab) stays until one row is picked. After
  a bulk delete nothing is selected; rows are kept by session id.
- Closing a screen with several rows selected clears them; one row is kept.
- Show and Hide set every row, not a toggle; each bulk action saves once;
  any other press disarms Delete.
- A new key `list.moreSelected` rather than reusing a tooltip's "more".
- Side panel: Ctrl/Shift + click moves no map and picks no placement; a
  layer or dimension change drops several rows. Shapes: the draft row never
  takes part; starting a draft clears the rows.
