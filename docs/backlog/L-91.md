# L-91 Shield glint missing in Lamium's item icons

Kind: Research
Status: Parked; cause known, the fix needs a different draw path (maintainer's call). Known issue

Lamium's own item icons (container previews, the L-75 offhand slot,
durability HUD, enchantment order) miss things vanilla slots show.

Still wrong (maintainer, last checked 2026-11-12 on `d96f2cbe`, 1.26.60.05):
- An enchanted shield shows no glint.
- Enchanted leather armor's undyeable parts draw see-through (plain leather
  is fine through the shared-mesh path `inspection/render/ItemIcon`; glinting
  items take the direct path for their glint, L-142). Also in the
  enchantment order's icons. Maintainer: recorded, not now.
- A recovery compass draws nothing in a container preview (a compass does);
  its icon is data-driven.
- Heads (piglin, dragon, creeper, ...) in a shulker box preview: drawn if
  that box was opened once since entering the world, not drawn if the head
  has sat in a never-opened box since before (2026-11-13, `6f70bdb2`).
  Drawing the same head elsewhere does not help. Not looked into.

## Decided
- Keep `Item::isGlint` as the glint predicate; do not use `isEnchanted`.

## Open
- Heads: where the two cases' item data differ (Item details on shows the
  stored data in the tooltip). Read that first.

## Next
If resumed (a larger change): draw these icons through the vanilla slot
path, e.g. drive an `InventoryItemRenderer` (or its pass setup) from
Lamium; that could fix the shield glint, leather and model items together.

Findings (VALIDATION-LOG 2026-10-06, `icon_trace`):
- Lamium uses `ItemRenderer::renderGuiItemNew` plus a foil call when
  `isGlint`. Vanilla slots are `InventoryItemRenderer`, a UI custom renderer
  whose passes the UI batch prepares (material per pass, two texture slots)
  before `renderGuiItemInChunk`.
- Leather: one slot pass, UI material `Item` (13), chunk type 2, one
  `iconBlit` with Lamium's exact arguments. `renderGuiItemNew` drops the
  undyeable pixels with every material; vanilla's equip animation, which
  uses it too, shows the same gap. Not a missing argument.
- Glint: flat icons get three slot passes (`ItemGlintStencil` chunk 2,
  `InventoryItemGlint` chunk 4, `ItemUnglintStencil` chunk 5); Lamium's one
  foil call at 1.35 matches them. The shield is a model (`Shield` material,
  chunk 7) and the foil call draws nothing for it.

## Tried
- Other materials for leather with `renderGuiItemNew` (plain icon,
  multi-color tint, UI `Item`, entity change-color): all drop the layer or
  draw the background.
- `renderGuiItemInChunk` outside a slot: a flat tint square (no batch setup).
- One shield glint round under L-119 failed (record in done/L-119.md).
- Another mod's item-icon path (2026-11-14, `8e00a4b1`, removed): same
  structure and same gaps; its draw-context differences (off-screen quad
  flushed with `ui_flush`, zOrder 0, foil at icon alpha without the shader
  tint), alone or together, drew no shield glint. No lead there.
