# L-91 Shield glint missing in Lamium's item icons

Kind: Research
Status: Waiting for the maintainer: whether to drive a vanilla slot renderer for the shield glint. Known issue

Lamium's own item icons (container previews, the L-75 offhand slot,
durability HUD, enchantment order) miss things vanilla slots show.

Still wrong (maintainer, checked 2026-11-17 on `03d52af7`'s build, 1.26.60.05):
- An enchanted shield shows no glint (looks like a plain shield).
- Heads (piglin, dragon, creeper, ...) in a shulker box preview: drawn if
  that box was opened once since entering the world, not drawn if the head
  has sat in a never-opened box since before (2026-11-13, `6f70bdb2`).
  Drawing the same head elsewhere does not help. Not looked into.

## Decided
- Keep `Item::isGlint` as the glint predicate; do not use `isEnchanted`.
- A glinting flat item draws as its slot's three passes, each a shared-mesh
  batch (`inspection/render/ItemIcon`): UI material 6 ItemGlintStencil
  (chunk 2), 5 InventoryItemGlint with `textures/misc/enchanted_item_glint`
  (chunk 4), 7 ItemUnglintStencil (chunk 5). This fixed enchanted leather's
  undyeable parts (2026-11-17). Shields and `IconAt::direct` icons keep the
  direct path (`renderGuiItemNew` plus a foil call).

## Open
- Shield: the remaining route is driving a vanilla slot as the UI does: a
  `CustomRenderComponent` holding a clone of a slot's
  `InventoryItemRenderer`, drawn per pass through the context's
  `renderCustom` (which applies the default batch's material and textures)
  after its `preRenderSetup`. Game objects Lamium does not own today,
  version-sensitive, crash risk. The maintainer decides.
- Heads: where the two cases' item data differ (Item details on shows the
  stored data in the tooltip). Read that first.

## Known
Slot trace 2026-11-17 (VALIDATION-LOG, `icon_trace`):
- Enchanted flat items: one shared-mesh batch (type 1), passes m6 / m5 / m7
  as above; only the glint pass asks for `preRenderSetup` (the glint shows
  and moves without it).
- Shield: a default batch (type 0), passes 9 Shield (chunk 7), 5 (chunk 4),
  7 (chunk 5), texture slot 0 empty; plain shield one pass 9.
- `renderGuiItemNew` drops leather's undyeable pixels with every material.
- The glint pass's chunk call (type 4) sets the glint constants itself
  (`ActorShaderManager::setupShaderParameters`: color (0.28,0.14,0.46),
  rotations -20/80, UV scale 0.5 for the shield, 16x32 for flat icons),
  for Lamium's calls as for a slot's: the constants are not what is missing.

## Tried
- Other materials for leather with `renderGuiItemNew` (plain icon,
  multi-color tint, UI `Item`, entity change-color): all drop the layer or
  draw the background.
- `renderGuiItemInChunk` outside a slot: a flat tint square (no batch setup).
- One shield glint round under L-119 failed (record in done/L-119.md).
- Shield as its slot's three passes in shared-mesh batches (9/7, 5/4, 7/5,
  2026-11-17): the shield drew, without a glint.
- The shield's base drawn directly, then vanilla's last glint constants
  replayed before the glint and unglint batches (2026-11-17): no glint.
- Another mod's item-icon path (2026-11-14, `8e00a4b1`, removed): same
  structure and same gaps; its draw-context differences (off-screen quad
  flushed with `ui_flush`, zOrder 0, foil at icon alpha without the shader
  tint), alone or together, drew no shield glint. No lead there.
