# L-419 Enchantment Order: planner and anvil panel slips

Kind: Ready (Bug) (strong model)
Status: Open, not started (from L-342, rechecked in code 2026-11-28)

Slips in Enchantment Order found by the 2026-11-14 review and still true in
code on 2026-11-28. Nothing here was seen in game.

## Decided
- The hover split of "needed at once" and "work penalty" follows the drawn
  text (the hit test splits at width/2, `EnchantLayout.h`; the text is
  drawn at onceWidth + 12, `EnchantSteps.cpp`).
- An off row has no - and + area: `hit` returns RowMinus/RowPlus without
  checking `levelStepper`.
- An item past 10 anvil uses does not read "every order is refused" in
  Creative (`plan()` returns nothing above work 10, `EnchantPlan.h`).
- Clicks stop hitting the cached frame once the anvil closes: `pressState`
  clears only in `endAnvil`, 500 ms after the anvil was last seen.
- A book-limit warning leaves the settings footer on Esc too (only the
  Back button calls `clearMessage`).
- The plan matches stacks by their anvil uses as well as slot and
  enchantments (`sideOf`), so a held plain or single-enchantment book is
  told from a fresh one where the uses differ.
- Left as they are: the level warning compares with the plan's dearest
  step (documented in ENCHANT-ORDER.md); planning both goals per change
  (at most 10 inputs).
