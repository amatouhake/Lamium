# L-153 Prefer the last pressed opposing movement key

Kind: Design, then Research for the native input boundary
Status: Pure model built and tested; no input hook, setting or action; release behavior and default not chosen

Optionally resolve simultaneous W/S or A/D input to the last pressed
direction (vanilla cancels opposing keys).

## Decided
- Model event sequences in pure logic before touching gameplay input; menus
  and focus changes must not leave stale held inputs.
- `src/input/OpposingKeys.h` resolves one axis from press, release and clear
  events; `tests/OpposingKeysTests.cpp` covers auto-repeat, stray releases
  and clearing on focus loss. Both release behaviors are modelled.

## Open
Choices for the maintainer, with the agent's recommendation (not decided):
- Release/resume: when the winning key is released while the other is still
  held, the held key takes over (`Held`) or nothing moves until it is
  pressed again (`Repress`). Recommended `Held`: it matches rocking between
  two keys; `Repress` reads as a dropped input.
- Default: recommended off, since it changes vanilla movement.
- Interaction with remapped keys, controllers, permanent movement and
  detached cameras.

## Next
Research where vanilla turns key state into the move vector, so the result
replaces only the cancelled case, and what controllers and permanent
movement feed into the same place.
