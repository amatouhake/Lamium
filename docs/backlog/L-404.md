# L-404 Keep the includes between source areas from growing

Kind: Refactor
Status: Open; the check is not agreed

AGENTS.md draws `app`, `settings`, `input`, `ui`, `overlay` and `features`
as layers, but the include graph between them is one cycle through all 16
areas (each feature folder counted as one). No file-level include cycle
exists, and most of it is harmless; nothing stops it growing.

## Open
- A baseline check like `Check-UiTokens.ps1`: the area-to-area include
  edges that exist today are listed, and a new edge fails until it is added
  on purpose. Or nothing, and review by hand.
- Whether the shared pure vocabulary other features include from a feature
  (`schematic/Nbt.h`, `schematic/RayCells.h`, `schematic/SchematicItems.h`,
  `inspection/render/ItemIcon.h`) moves to a place no feature owns.
- Whether `Settings.h` keeps including the features' enum headers.

## Known
- `settings/Settings.h` includes eight feature headers, `ui/HudElement.h`,
  `input/Binding.h` and `overlay/LightMode.h` for the types of its fields
  (all pure). `app/Runtime.h` includes `Settings.h` and is included from 113
  files in other areas, so a change to any of those headers rebuilds most
  of the mod; `Settings.h` changed in 102 commits between 2026-10-11 and
  2026-11-24.
- `input/Actions.cpp` includes 27 feature and UI headers and
  `input/CustomInput.cpp` 13: the dispatch knows every feature (rule 5).
- `overlay/WorldOverlay.cpp` includes five features' headers and draws the
  block highlight's glow itself.
- Features that include each other: information and schematic, information
  and map, map and schematic; recipes includes schematic.
  `camera/CameraSessions.h` is included from 18 files in other areas.
