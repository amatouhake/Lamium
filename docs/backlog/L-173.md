# L-173 Quick shapes: a beacon's range at a glance, shapes that are not saved

Kind: Design.
Status: Direction decided (2026-11-06); waiting for the in-game range check.

See a beacon's range without making a shape by hand (kind, center, radius,
saving). From the maintainer's notes (2026-10-13).

## Decided
- No separate temporary ("quick") shapes: they would make the player check
  again after every login. This replaces the earlier quick-shape proposal.
- One action on an aimed beacon creates an ordinary shape: saved, listed,
  shown on the maps and edited like any other. A Box should hold it with no
  file format change. It is a copy of the range when made, so a changed
  pyramid needs a new one; on a server it goes at rejoin as every shape does.
  The Shapes editing and saving flow stays as it is.

## Open
- The range's exact width and vertical extent per level, as Bedrock behaves.
- Where the action lives (key, radial menu).
- Whether the pyramid's levels set the size where they can be read, with the
  shown size marked as assumed otherwise (from the earlier proposal).

## Next
Check in game the range's width and vertical extent, then choose the key or
menu. Header read (SDK 26.60.4, not confirmed in game): `BeaconBlockActor`
has `mNumLevels` and `mNumLevelsSet` as plain members and gets its state
through `_onUpdatePacket`, so the level count is probably readable from the
client's block actor, also on a server. No range or radius member exists:
the size per level comes from the in-game check and lives in a pure, tested
table in Lamium.
