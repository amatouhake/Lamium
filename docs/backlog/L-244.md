# L-244 FreeCamera keeps the inside-a-block view after starting in a block

Kind: Bug, parked as research
Status: Parked (maintainer 2026-10-27) until a path to the renderer that draws the effect is found; left vanilla

Starting FreeCamera with the body's head inside a block keeps the
inside-a-block screen effect the whole time, also while flying in the air.
Leaving FreeCamera restores the view; not a release blocker.

## Decided
- While FreeCamera owns the view the effect is not drawn; outside FreeCamera
  it stays vanilla (maintainer 2026-10-26). Any suppression path goes in
  GAME-UPDATES.md, is gated by `versionSensitiveAllowed()` and fails open.
- Resume only with a new path; the exposed SDK paths are closed (Tried).

## Next
When resuming, check in game: start FreeCamera with the head buried and fly
out; leave FreeCamera while still buried (the effect returns); Freelook and
the ordinary view unchanged.

## Tried
- Clearing `ViewRenderData::mDrawInsideCubes` on the frame's copy from
  `LevelRendererPlayer::createViewRenderObject`: a probe showed the flag
  cleared every frame and the effect still drawn; the flag is not the
  driver. Hook removed (`73584825`).
- Returning null from `Actor::getInsideBlock()` under FreeCamera: instant
  crash (0xC0000005, `mov rax, [rax+0x68]`, RAX = 0;
  `logs/crash/trace_2026-10-27_10-13-33.log`); the answer is dereferenced
  without a null check, so this path is closed.
- `InsideCubeRenderer` and `InsideBlockEffect` are empty in the SDK headers.
