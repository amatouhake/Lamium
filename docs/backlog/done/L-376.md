# L-376 Recipe view tabs per process, stations named once

Kind: Design
Status: Done 2026-11-20, checked in game (VALIDATION-LOG); placing a cooking recipe moved to L-380

The recipe view's tabs and where it says which stations make a recipe.
[L-371](../L-371.md) first agreed one tab per kind of work with stations on
each recipe; seen in game, that was turned back to tabs per process.

## Decided
- Tabs per process, as other recipe viewers keep them (maintainer
  2026-11-20, after a first build with one cooking tab and stations on
  each recipe, [demos/recipe-kinds.html](../../demos/recipe-kinds.html)):
  crafting, smelting, blasting, smoking, campfire cooking, stonecutting,
  smithing; later brewing ([L-361](L-361.md)) and the like. One cooking
  recipe the game files under several stations' tags is one recipe in
  the index (the plan and the notes see it once) and shows in each tab
  whose process does it.
- A tab's stations stand once in the heading's second line, before the
  process's name, for every kind (crafting: the crafting table), as items
  like any other: the item's tooltip, a press its recipes, a right press
  its uses. A tab's own icon is one usual station (campfire cooking: the
  campfire); its tip and the heading name the process alone, no station
  list (maintainer 2026-11-20: the list read worse).
- A station's recipes (R, a left press) are how it is made; its uses (U,
  a right press) first what it does, then the recipes it goes into, none
  twice. That first tab names all its process's stations, as the
  process's tab does elsewhere (both campfires), its recipes those the
  station does.
- The plan does not count fuel, so it needs no station choice.

## Known
- A merged recipe keeps its first station (the furnace for cooking) in
  the notes' key, so `recipes.json` did not change; a choice made at
  another station (blast furnace) before is no longer found.
- Smelting alternatives (raw iron or the ores) group only where their
  stations are the same, as they are in the game.
