# L-403 Diagnostic build options: remove with their item, or keep them compiling

Kind: Refactor
Status: Done 2026-11-26; policy A chosen by the maintainer, 16 options deleted; meant to change nothing in game, not checked there

`xmake.lua` had 43 diagnostic options (trace, probe, perf), none built in
CI, so an SDK move broke them unseen. Now 27 are left: they name an open
item, are standing tools, or name no item at all.

## Decided
- A trace leaves with its item (policy A, 2026-11-26): when an L-item
  closes, its option, its Trace or Probe files, its `#if` guards and its
  inventory entries in GAME-UPDATES.md are deleted in the same commit; git
  keeps them. No CI job compiles diagnostic options (policy B not taken).
- Deleted now (they named only finished items): `slime_trace`,
  `playerlist_trace`, `portal_trace`, `trade_trace`, `slot_trace`,
  `creative_trace`, `hunger_trace`, `consumption_trace`, `offhand_trace`,
  `pick_trace`, `sneak_trace`, `book_paste_trace`, `effects_trace`,
  `edge_guard_perf`, `schematic_quad_trace`, `doll_trace`.
- Kept: `edge_trace` (L-406 Edge Guard reads the client's player while
  guarding the local server's copy needs it), `research_trace` (L-59),
  `restock_trace` (L-299), `radar_icon_probe` (L-330), the standing tools
  `unverified_game` and `feature_skip`, and every option naming an open
  item.
- A deleted trace's `#else` stubs went too (Fake Offhand's choice and
  restore trace calls, Book Paste's trace macro), not only its `#if` blocks.

## Known
- With the kept `research_trace`, `restock_trace`, `edge_trace`,
  `radar_icon_probe`, `world_probe` and `recipe_trace` on, the build
  compiles but 16 game symbols do not link, the same before and after the
  deletion (2026-11-26). `restock_trace` needed a missing include.
- L-79 Carved pumpkin and spyglass frame draw path may want the effects
  trace back; its item file says where git has it.
- A trace option stays on in `xmake f` until given `=n`.
