# L-406 Edge Guard reads the client's player while guarding the local server's copy

Kind: Research **(strong model)**
Status: Done 2026-11-27; fixed with a client-thread snapshot (`b8e035b1`), seen in a local world

In a local world Edge Guard also guards the integrated server's copy of the
player. `guard()` in `src/features/interaction/EdgeGuard.cpp` takes the
client's `LocalPlayer` first and reads its box and movement state, then
compares the entity being moved against it. The comment above
`clientThread` in the same file says a local world's server computes move
vectors on its own thread and client state is read only on the client's.
If `guard()` runs on the server's thread for the server's copy, it reads
the client's player from another thread. L-73 Architecture review fixed the
same kind of slip in Breaking Restriction and Tool Switch (its item A).

## Decided (maintainer 2026-11-27)
- The server path reads a snapshot of the client player (box, walking
  state, time) that the client thread records on each of its own moves;
  older than 250 ms, the server copy is not guarded. The client thread
  keeps the old logic (its own player, or an entity whose box matches).

## Known
- Seen 2026-11-27 (an `edge_thread_trace` build, since removed): `guard()`
  runs for the client's copy on the client thread and for the server's copy
  on another thread, which read the client's `LocalPlayer` across threads.
- `edge_trace` (L-160/L-162) no longer links on 1.26.60: five trace hooks
  (`ActorHistory::addFrame`, `prepareEntityForRewindFromCapture`,
  `applyHistoryChangesToLiveEntity`, `$tickMovementCorrectionReplay`, the
  correction packet's `$handle`) lost their symbols.

## Done
- Seen 2026-11-27 on `b8e035b1`: walking, sprinting, diagonal and sneak
  approaches stop at the edge in a local world; the log still says the
  server's copy is guarded.
- `edge_trace` left with this item (L-403 policy A); its trace hooks had
  stopped linking on 1.26.60. A later item restores what it needs from git.
