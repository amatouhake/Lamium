# L-381 Place a recipe while the pointer holds something

Kind: Research
Status: Done 2026-11-21, built and checked in game (VALIDATION-LOG); a server unchecked

Lamium lays a recipe in as a hand would: each ingredient taken onto the
pointer and put down in its cell (`RecipePlace.cpp`). With something on
the pointer it cannot, so a press that would place shows the recipes
instead. The game's recipe book places with the pointer full, by one
request of its own that does not go through the pointer (maintainer
2026-11-21, while checking [L-379](L-379.md)). The aim: every press
behaves as without the pointer's stack, which stays where it is.

## Found
- The game's recipe book fills the grid with one request a cell, not
  through the pointer (VALIDATION-LOG 2026-11-18). The manager's virtual
  `handlePlaceAmount(src, amount, dst)`, which Sort and Item transfer
  use, moves a stack from an inventory slot straight into a grid cell;
  the pointer keeps what it holds. The recipe book's own calls in the
  SDK (`_handleRecipeSelect`, `_recipeAutoCraft`) were not needed.

## Decided and built (maintainer 2026-11-21)
- Every cell goes straight from its slot; where a move shows nothing, it
  goes through the pointer while that is empty.
- A held stack never moves: a press and Shift + press place as without
  it; Ctrl + press stacks the round onto the held product while there is
  room, and with another item held or no room lays the round in only
  (the place button's tip says so). No stack is set down.
