# L-374 Bands built from regions and pages

Kind: Refactor (strong model)
Status: Done 2026-11-20, the default checked in game (VALIDATION-LOG); other layouts with L-375

The item screens' side lists are built in code as fixed halves (favourites
and wanted left, the item list right) inside `ItemList.cpp`, which also
holds the search field and the input. Rebuild them on the model agreed in
[L-371](../L-371.md) "Decided: the bands' arrangement", with no editor yet:
regions beside, above and below the game's window, panels split along a
region, one page to a panel, each feature's pages its own.

## Decided
- What shows does not change: the default layout is today's (favourites
  over wanted on the left, the item list on the right).
- The layout is kept in the settings as regions of panels with shares;
  a page whose feature is off is left out where it stands, and comes
  back with it.
- Each panel keeps one row; a smaller screen shrinks panels in
  proportion; a region too low for one row shows its panels at the foot
  of a side region on that screen only. Nothing is dimmed where no panel
  lies.
- The pure part (regions from the game's window, panel boxes, the
  lending) is a header with tests; `ItemList.cpp` is split so each page
  draws itself.

## Known
- The open container's line lies in the left region's last panel: in the
  plan's rows' room when that is the plan, else that panel gives up its
  units, so opening a chest moves nothing above it.
