# L-394 Target card banner icon shows its color but not its patterns

Kind: Ready (Bug)
Status: Done 2026-11-23, checked in game (VALIDATION-LOG)

The target card draws a block's icon from its pick item's name and aux. A
banner's base color is the aux, so a black banner shows black, but its
patterns are block entity data and were left out. Inventory HUD draws
patterned banners right (maintainer, 2026-11-23), so the shared icon
drawing is not the problem.

## Decided
- Banners (`minecraft:standing_banner`, `minecraft:wall_banner`) join item
  frames in `blockIcon` (`TargetInfo.cpp`): the icon's item data is built
  from the banner's saved block entity (`savedBlockEntity`), not taken from
  the pick item, which for frames carried no data (L-393).
- `bannerItemData` (`TargetCard.h`, tested): the pick item's name, aux as
  `Damage`, Count 1, and the saved `Base`, `Patterns` and `Type` (ominous)
  as the item's `tag`. A banner with neither patterns nor a type keeps name
  and aux. The saved position and id stay out of the item.
- Same 250 ms memo per position as frames; the decoded stack is drawn as
  L-393 draws it (glint pass, fallback to name and aux).
- Other blocks still keep name and aux (L-393's decision).

## Result
Checked on `cf62ddae` against Inventory HUD: complex patterns standing and
on a wall, an ominous banner, and a plain colored banner as before.
