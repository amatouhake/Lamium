# L-404 Keep the includes between source areas from growing

Kind: Refactor
Status: Done 2026-11-26; `scripts/Check-Includes.ps1` runs in CI

AGENTS.md draws `app`, `settings`, `input`, `ui`, `overlay` and `features`
as layers, but the include graph between them is one cycle through all
areas (each feature folder counted as one). No file-level include cycle
exists, and most of it is harmless; the check stops it growing unseen.

## Decided (maintainer 2026-11-26)
- `Check-Includes.ps1` lists the area-to-area edges that exist in
  `scripts/IncludeBaseline.txt` (one `from to` line each, about 125 on
  2026-11-26). An include that makes a new edge fails until the edge is
  added on purpose with `-Update`; an edge that is gone fails too, so the
  baseline only shrinks. SDK and library includes are not areas.
- The shared pure vocabulary other features include from a feature
  (`schematic/Nbt.h`, `schematic/RayCells.h`) stays where it is: moving it
  gains little, and `SchematicItems.h` and `inspection/render/ItemIcon.h`
  take game types, so they are not pure vocabulary.
- `Settings.h` keeps including the features' enum headers.
- A feature's screen lives in its feature folder (L-399).
