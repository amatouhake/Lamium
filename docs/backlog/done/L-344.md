# L-344 English Search does not find enchanted books by enchantment name

Kind: Ready (Bug against the player's expectation)
Status: Done 2026-11-15 on `10325a18`, confirmed in game by the maintainer

With English Search on, typing an enchantment's English name ("protection",
"knockback") in the Creative search field does not find the enchanted books
that carry it.

## Decided
- English Search only adds matches, never hides what vanilla finds; a query
  matches when every word is in the item's English display name or its
  identifier without the namespace (L-130, see its record).
- Scope (maintainer 2026-11-15): an enchanted book also matches by the
  English names of its stored enchantments, in Creative search only.
  Other enchanted items and the recipe book may follow later.
- Cause (confirmed in `src/features/inspection/EnglishSearch.cpp`): the
  hook matched only the description id's en_US name ("Enchanted Book") and
  the identifier `enchanted_book`; the stored enchantments were never read.
- Built: for `minecraft:enchanted_book` the hook also matches each stored
  enchantment's en_US name (`Enchant::mDescription` as an `enchantment.`
  key) and its identifier (`mStringId`, `fire_aspect`). Words may combine
  with the book's own name ("enchanted protection").
- Creative only without a separate check: the hook is shared with the
  recipe book, but enchanted books have no recipe there, so the addition
  only shows in Creative search (agent's choice, overnight 2026-11-15).
- Not gated by `versionSensitiveAllowed()`: it only reads and only adds
  matches; a wrong read means no extra match (vanilla).

## Check in game
Game in Japanese, English Search on, Creative: "protection", "knockback",
"bane" find their books; the log shows `English search: enchantment ...`.
