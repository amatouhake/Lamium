# L-401 Per-frame work apart from the HUD's drawing

Kind: Refactor
Status: Done 2026-11-24 on `f0a1de52`, checked in game on `6f51abdd` by the maintainer

`information::drawHud` drew the HUD and also ran what must happen every
frame of play: map recording, the death point and waypoint arrival, and the
notices other features leave for a toast (a finished map merge, a world
that differs from its saved data, a saved schematic area, skipped server
packs, capped block highlights). That the map records while the HUD is
hidden (MAP.md) held because of where a call sat inside the draw function,
and the toast's own code (`ui/Toast.h`) was implemented in `InfoHud.cpp`.
Both are apart from the HUD now; behavior is meant to be the same.

## Decided
- The per-frame work becomes one function, called from the place that calls
  `drawHud` in play, under the same condition (the gameplay screen's HUD
  view) and before it, so a toast raised there still shows the same frame.
- Drawing stays in the HUD: the waypoint markers. The schematic adjust
  key's step draws nothing (it took the render context only for its
  client), so it moved with the rest.
- The layout editor's preview keeps running none of it.
- The world map screen's own `map::record` call and the settings screen's
  `stepMerge` stay: they cover frames where the HUD is not drawn.
- The toast implementation moves to `src/ui/Toast.cpp` unchanged.

## Known
- `app/PlayFrame.cpp` `playFrame(client)` is called from the screen hook in
  `SettingsScreen.cpp` just before `drawHud`. Its lines are the ones that
  were in `drawHud`, in the same order.
- `drawHud` has three callers: the play HUD in `SettingsScreen.cpp` (no
  preview) and two in `HudEditor.cpp` (with a preview).
- `information` and `map` include each other (the HUD draws the minimap;
  the minimap uses the HUD's line ids, slime rule and biome names). Not
  part of this item.
