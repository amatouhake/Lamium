# L-407 Two small leftovers from the 2026-11-24 architecture review

Kind: Refactor
Status: Done 2026-11-26; built and LamiumTests pass, not checked in game

Neither changes behavior.

## Decided
- Per-frame and per-tick reads of the settings take `Runtime::snapshot()`
  (the published copy, no copy made) instead of `preferences()`, which
  copies the whole `Settings`: the play HUD and the world map in
  `SettingsScreen.cpp`, key sync (`CustomInput.cpp`), container previews,
  Periodic input, the schematic notice, Hand restock, Tool Guard, the world
  map's reads, the item list and the plan view. A value kept past one
  expression holds the `shared_ptr`, not a reference into a temporary.
  `preferences()` stays for code that changes a copy and saves it.
- The recipe table's thread is joined by `service::stop()`, as the map
  store joins its worker, so a disable leaves nothing running. At process
  exit nothing calls `stop()`, so the thread is detached then instead of
  `std::thread`'s destructor ending the process (L-314 Silent crash when
  Minecraft exits on 1.26.60).
