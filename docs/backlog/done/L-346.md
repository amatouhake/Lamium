# L-346 One input behavior for steppers and buttons

Kind: Refactor (agreed 2026-11-15)
Status: Done 2026-11-15 on `e43634c4`, confirmed in game by the maintainer

Since [L-341](L-341.md) steppers and buttons look the same everywhere,
but each screen still handles their presses itself, so they behave
differently. Goal: one rule per control, in DESIGN "Controls", and the press
handling shared where the drawing already is.

## Known
- Shift for ten steps exists only on the schematic save corners (and the
  HUD editor's arrow-key nudge); every other stepper steps by one.
- Right click: on a settings row it steps the value down anywhere on the
  row; in the tool views (Shapes, Waypoints, Schematics) it counts as a left
  click on their buttons, so it can arm and then run Delete; pages and the
  data notice ignore it.
- A typed number out of range: settings rows draw the stepper in warning
  color and keep the old value; HUD scale draws its text in warning color;
  the tool views drop it without a word.

## Decided
- Right click never presses a button (Delete included); on a stepper it
  steps down like the `-` end; elsewhere it does nothing. A settings row
  keeps stepping down anywhere on the row (the row is its stepper).
- Shift + an end steps ten of that stepper's own steps (0.1 becomes 1, 5 %
  becomes 50 %); choices ignore Shift.
- A typed value out of range becomes the nearest end when the edit is kept
  (Enter, Tab, a click outside); while typing it is not applied, and the
  stepper shows warning color where it already did.
