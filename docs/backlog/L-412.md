# L-412 One overlap check for bindings, fixed presses and the game's keys

Kind: Ready **(strong model)**
Status: Choices agreed 2026-11-27 (maintainer); building

L-372 settled where actions work and warns about the game's keys, but
overlaps still come from four sources checked in different places: other
bindings (`input::bindingConflicts`), the game's click (`gameClick`), the
game's keys (`gameKeyUse`) and fixed presses (`input::fixedPresses`). Each
display (key cell, tip, capture line, footer after binding, Find by key)
picks up a different subset, so the player cannot always tell how much a
key is shared.

## Known (read in code 2026-11-27, not seen in game)
- Fixed presses take part in no check: Sort on Ctrl + Wheel silently
  stops Item transfer's Ctrl + Wheel (the binding is consumed first,
  `CustomInput.cpp`), and neither row warns.
- The fixed data itself gives Shift + click two meanings on an item screen
  (Recipes' list, Item transfer's slot), told apart only by target.
- The game's click is warned only for play actions, yet at runtime a lone
  mouse button passes through on item screens too: ShowRecipes on Left
  click fires with the slot's click and Recipes' own click, unmarked.
- A plain C binding likely fires on Ctrl + Alt + C too (extra held
  modifiers are accepted), so it may take the game's coordinate copy,
  which L-372 stopped warning about. Not seen in game.
- The tip's count is Lamium overlaps only: a game key fills the caps
  while the header says "1 overlap", or shows no count at all.
- The capture line and the footer show only the game note; Find by key
  never finds the game's use of a key; only the first game key is named.
- In the recipe view every key goes to Lamium, so the game's hotbar and
  drop keys never reach the game there, and the inventory key is
  Lamium's close, yet the fixed "close" lists only Esc.

## Decided (maintainer 2026-11-27)
- Fixed presses join the check: a binding that takes one warns like an
  overlap with another binding, and the fixed row's tip lists it.
- The game's click warns on item screens too (the screen's click also
  happens); the click still goes through.
- The game's own modifier chords pass: when the keys held are exactly one
  of the game's Ctrl + Alt or Alt keys (coordinate copies, macros), a
  binding without those modifiers does not fire and the game gets them.
- One list of overlaps for every display: the tip's count includes the
  game and fixed presses; the capture line and the footer after binding
  name Lamium overlaps too; Find by key says in the footer when the game
  uses the key.
- Correction, no choice: the recipe view takes every key, so the game's
  keys are not warned there, and its close lists the inventory key.
