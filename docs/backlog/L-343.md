# L-343 A server's map, waypoints and placements are lost when its address changes

Kind: Bug. Research for the identity, then Design for moving existing data
(it touches saved data: agree before building).
Status: Parts 1-3 built and checked in game (not with a friend's world); part 4 (merging) open; a Realm and a changing port not seen

A server's data lives in a folder and file named after the connection's
address and port (`resolve` in `src/features/map/WaypointSession.cpp`,
`serverFileName` in `Waypoints.h`), so a server reached under another name
starts empty (Discord 2026-11: a Realm's map back to 0 MB after
reconnecting; the maintainer: servers behind a proxy plugin that makes even
vanilla treat each visit as a new server). Old data stays under its old
name in `mods/Lamium/config/` (`map`, `waypoints`, `schematics`,
`death-layouts`). Hosts, IPs, ports and level ids here are stand-ins.

## Decided
- **A different port is never the same server by rule**: several servers on
  one address differ only by port (maintainer 2026-11-14, their own setup).
  Where nothing reliable identifies a server, the player chooses and the
  default stays address and port.
- Names: the url form `http://host:port` gave `http___host_port_port`; a new
  server is now named `<host>_<port>`, without scheme. A join without an
  address (a friend's world) saves under the level id (`world_<hex of id>`);
  nothing was saved for those before.
- `config/servers.json` (`ServerIdentity.h`, tested) records per server the
  key its data is under, the names it was joined by, its last IP, the port
  and the last level id. A join belongs to a record when the port is the
  same and it was joined by this name before, or it is at this IP now, the
  level id does not say otherwise and no name says otherwise. A record
  keeps its key whatever its folders hold later. Only a join that brings
  something new compares the old name forms and takes the one holding the
  most (documents first, then map size); names passed over are not compared
  again. Nothing is merged, moved or deleted; the log names the key.
- One key carries all four kinds of data (map, waypoints, placements, death
  layout); the map is not chosen on its own (maintainer 2026-11-14).
- The player's choice (part 3): General > "Saved data" (Open button, child
  row naming the data in use; the same child row under Waypoints, World map
  and Schematics). The page keeps the sidebar and lists servers', friends'
  and local worlds' data with tags, no group headings; rows are named by
  their own key (`shownName`), the data in use first even when empty; a
  candidate's mark says why ("Same level ID", "Same address", "Used
  before"). Details: waypoints, placements, map size, last use, level id,
  "Used by", and an Overworld map picture (`MapThumbnail.h`,
  `ui/SavedDataThumb`, one region read per frame, centered on the newest
  region file). "Use this data" takes effect at once (`useData`). The
  any-port switch (`Entry::anyPort`) sits above it; while on, the address's
  other records are passed over, not erased, and a port given other data
  meanwhile keeps it (`Entry::pinned`). Delete, pressed twice, on its own
  row, never for the data in use.
- Notice (`ui/DataNotice`): while another candidate holds more than the data
  in use, the Waypoints screen, all Schematics tabs but Files and the world
  map say whose and how much, with "Use this data", "Saved data" and "Do
  not show again" (per server, `Entry::quiet`). Worked out at a join and
  after a change, not per frame.

## Open
- 4: whether data found to be one server is ever merged (waypoint lists
  could be; map tiles less obviously), or only chosen between.
- A world without an address that sends a plain name as its level id would
  share data with others sending the same. Not seen.
- A join by IP finds data under the host name only after a join by name, or
  by the player's choice.

## Tried
Seen 2026-11-14 (each joined twice, all stable): `mRakNetGUID` unset,
`mNetherNetId` empty (its Realms UUID form untested), `mTransportType`
"unknown" for remote joins: none identifies a server. The level id told one
network's backends apart but is whatever the server's config says
(`local_world` is a likely default): not an identity alone. After a
transfer the url carries the IP, so a backend gets two names.
