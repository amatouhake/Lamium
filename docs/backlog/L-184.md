# L-184 Inspect ghost block data and schematic container contents

Kind: Design / Research.
Status: Partly done: target card and saved block entity rows shipped; file-only data (containers, comparator signal) open.

Inspect the ghost under the crosshair: expected block name, facing,
BlockState and saved Block Entity data, including inventories of barrels,
hoppers and other containers and data relevant to redstone output (for
example comparator signal), without assuming an on-world text overlay is the
right presentation for all of it.

## Decided
- Target card: the ordinary single-card layout (stacked and side-by-side
  sections were tried and dropped as hard to read). Target Info's "Show
  schematic information" turns ghost picking and difference rows on or off.
  Details in SCHEMATIC.md.
- A ghost's card follows the same rules as the real block's, from the file
  alone (maintainer 2026-11-03), so a difference between a ghost and its
  block comes from the data, never the presentation. The world never fills a
  gap: a value the file does not decide reads "Not set by the schematic".
- Saved block entity rows (L-300/L-301 rules) come from the placement's
  `block_entities` entry for the cell (`PlacementOverlap.h` `blockEntityAt`,
  turned and mirrored like the cells), complete even where the world's copy
  is not. A note block's instrument comes from the file's blocks below and
  above; outside the file or at a void cell it is not set. A stored engaged
  `none` is normalised (`declaresNoInstrument`) so it does not swallow the row.
- Do not promise data the client or schematic never stored.

## Open
- Data only the file has (container contents, a comparator's signal) and how
  to present it: compact target-card rows versus an expanded inspection view;
  how to show inventory slots, NBT fields and signal values; what comes from
  the file versus current world state; absent or unsupported data;
  transform-aware directions.
- Kept in mind, not defects: a note block on the file's top or bottom layer
  always reads "Not set by the schematic" (the wording may want to name that
  reason); `fileCellAt` guards only `structure`, not visibility, dimension or
  layers as `blockEntityAt` does through `drawsCell`, safe while `ghostAlong`
  is its only caller; `GhostAt::blockEntity` points into the `structure` the
  same struct owns, a lifetime the type does not enforce.
