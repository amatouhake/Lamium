# L-353 Input events and the client thread: what is still touched outside the tick

Kind: Research
Status: The thread_trace build is ready; waiting for one session's log

Rule 2 (AGENTS.md) says key and mouse events arrive outside the client tick
and no game pointer is kept across frames. Code does not follow its wording
in two ways; nothing here is known to misbehave. L-405 Client pointers kept
across frames was merged into this item (maintainer 2026-11-26).

## Decided
- The thread-id log comes first; the rule or the code changes after it.
- No script flags stored game pointers (too many false hits).

## Known
- `IClientInstance*` is kept across frames in five places:
  `CameraSessions.h` (`client`, cleared on exit, dimension change and stop),
  `SchematicActions.cpp` (`adjustClient`, written each frame, never
  cleared), `WorldMap.cpp` (the screen's `client`, cleared on close),
  `PeriodicInput.cpp` (`button.client`, compared only, never read through)
  and `SettingsScreen.cpp` (`client`, cleared on close and exit).
- Three input listeners read through it: the camera's wheel listener,
  the schematic adjust wheel (`getScreenName()`), and the settings screen's
  `ownsTop()` (`sceneStack(*client)`) in its key and mouse listeners.
  `CustomInput.cpp` `process` asks `ll::service::getClientInstance()` on
  each event.
- The SDK does not show how long the client instance lives: `MinecraftGame`
  keeps them as `shared_ptr` by sub-client id and can add and remove
  sub-clients. `ClientExitLevelEvent` hands the instance over and the
  settings screen works with no world, so it outlives a world.
- `interaction::periodic::stop()` (from `Runtime::disable`) calls the game's
  button callbacks directly; a comment in `FakeOffhand.cpp` suggests a
  shutdown disable can run off the client thread. `scroll_drag::release()`
  also runs from the `onAppFocusLost` hook.

## Next
Deploy a build with `--thread_trace=y`; in one session enter a world, press
keys and click, Alt+Tab away and back, leave the world, quit the game. The
log's "Thread trace (L-353)" lines give each place's thread.
- If key, mouse, focus and disable share the client tick's thread: say so
  in rule 2 and in `CustomInput.cpp`, write the client instance into rule 2
  as kept while its owner is open and cleared on exit, and close this item.
- If not: the listeners' reads move behind the queue (the screen name and
  whether Lamium's screen is on top, captured on the tick; `adjustClient`
  becomes a flag), and `stop()` defers like `interrupt()`.
