# L-236 Rebuild only the ghost sections whose visible layer changed

Kind: Design, low priority
Status: Partly done: pure helper and tests built (2026-11-12); renderer step not started

Under the Up to cut, the ghost redraw after each step of the cut takes a
noticeable while on a large schematic (maintainer, desert village,
2026-10-22); Only is fine. Not urgent: day-to-day work likely uses Only.
The ghost cache key is per placement, so moving the cut discards and
rebuilds every 8-block section (and re-resolves the palette), including
sections whose shown cells did not change. Changing an unused field (Keep
under Only, Axis/Cut under All) already avoids a rebuild, because the key
covers only visible fields.

## Decided
- Each section gets a layer state, and unchanged sections are reused when
  the cut moves. `src/features/schematic/SectionLayers.h` gives a section's
  state under a `PlacedSlab` as a comparable value: hidden, whole, or the
  shown range on the cut's axis. Whole and hidden compare equal across
  axes, so only sections holding the cut differ when it moves.
  Tests: `tests/SectionLayersTests.cpp`.

## Next
The renderer step:
- The section mesh reads a halo of neighbour cells (`GhostMesh.cpp`,
  `halo`), so the range passed in must be widened by it, or a section next
  to the cut keeps faces toward a layer that has turned hidden (the test
  file has that case).
- The cache key takes the section's value instead of the placement's whole
  layer view.
- Palette resolution moves out of the per-section rebuild.
- In game: frame check on a large placement while stepping the cut.

A cheaper first step if it returns: keep the old sections drawn until their
replacements are built.
