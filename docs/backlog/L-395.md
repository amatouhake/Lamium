# L-395 Target card grows too large for signs and patterned banners

Kind: Ready
Status: Built, not checked in game (2026-11-23)

Every saved block entity field is a row (L-300), and a value could take up
to 60 % of the screen's width before it wrapped, so a sign or a patterned
banner made a card as wide as most of the screen. A sign's front and back
fields also read with the same labels, and the card's three information
keys flipped their row while held, unlike every other key beside a switch.

## Decided (maintainer, 2026-11-23)
- Keys: the keys of Other details, Show position and Show distance toggle
  their switch on each press, as DESIGN.md says a switch row's key does
  (this replaces L-308's hold-to-flip). No hold-to-peek command was asked
  for; action ids stay, so saved bindings are kept. Like other child
  switches' keys they switch the setting with Target Info off too, and the
  toast reads "Target Info > <row>".
- Block entity data has its own switch under Target Info, "Block entity
  data", with its own toggle key (new action `targetblockdata`). Other
  details keeps the block's states and the mob rows. On by default; a
  settings file from before (one with `targetStates` and no new key) takes
  Other details' value, so nobody's card changes. The note block
  capabilities follow Target Info with the new switch (`PausedFeatures.h`).
- Width: the value column is at most 120 GUI units (text scale) wide and
  a value wraps to up to 8 lines (first guesses, to tune in game); the
  card still never takes more than 60 % of the screen. No field is shortened per block: the rule is the
  same for every row (no block-specific code, maintainer).
- A field inside a compound is labelled "Parent > Field" (the child-name
  sign DESIGN.md uses), so a sign's front and back read apart.
- `BlockEntityVersion` is hidden with `id`, the position and the two
  per-actor flags: every block entity writes it. `TextOwner`,
  `PersistFormatting` and `Type` stay (L-300's every-field rule).

## Known
- A row with a change (a schematic's "before -> now") and a row with an
  icon or meter are neither capped nor wrapped, as before.
- The "Parent > Field" labels make a sign's label column wider, which takes
  back part of the width the value cap gains.
