# L-372 Hotkeys: where and on what each action works

Kind: Design, then Refactor
Status: Open; the direction is agreed (maintainer 2026-11-20), the details are not

Today a binding conflicts with another when their chords overlap and both
are gameplay actions or both item-screen actions. Every other case is
written into the code: Settings outside a world, FreeCamera's speed keys
only while it runs, Transfer in both, an open recipe view letting only the
recipe keys through, text fields taking every key. The recipe screens add
more places (the recipe view, the plan window, the layout editor of
[L-371](L-371.md), the search field) and presses on Lamium's own parts,
so the rule needs to say where an action works and on what.

## Decided (maintainer 2026-11-20)
- Lamium-wide, for every action, not only Recipes: each action declares
  where it works (a small fixed set of layers: gameplay, an item screen,
  a Lamium window over it, typing) and, where it matters, on what (the
  item under the pointer in Lamium's lists, a slot of the game's). Two
  bindings conflict only where both their layer and their target meet;
  the conflict tip says where.
- The code's special cases become these declarations.
- Presses on Lamium's own parts (left: recipes, right: uses, Shift and
  Ctrl with them, the wheel) stay fixed, not bindings, and are listed:
  Hotkeys shows them as read-only rows, like Item transfer's gestures,
  which are fixed and each switchable.

## Open
- The layers, exactly, and where Lamium's own screens (settings, world
  map, Schematics) and FreeCamera fit; whether a layer under another
  passes its actions up (an item screen's keys inside the recipe view).
- The targets, and whether a key (R, U) declares two.
- How Hotkeys shows a row's layer, and whether the fixed rows can be
  switched off one by one.
- One order for Esc and the game's inventory key: typing, a count being
  typed, the recipe view, the plan window, then the game's screen.
  Backspace steps back only inside the recipe view.
- A warning where an item-screen binding takes a key the game uses there
  (its inventory and drop keys, the hotbar numbers).

## Next
Agree the layers and targets with a list of every action against them
(an agent's draft), then a Hotkeys mockup. Settings ids and saved
bindings do not change.
