# L-417 Keyboard and Esc behave alike on every page

Kind: Design
Status: Open, not started; the Tab bug can be fixed first (from L-342, rechecked 2026-11-28)

Keys that act differently from page to page in the settings screen and its
tools, found by the 2026-11-14 review and still true in code on 2026-11-28.

## Decided
- Tab outside a world sticks at Hotkeys: the table's and the hotkeys' Tab
  calls `selectNav`, which refuses world-only pages, instead of the
  skipping `nextNav` the tool views use (`SettingsTableView.cpp` ~535).
  A bug with no choice open: Tab skips world-only pages.

## Open
- Esc in a search field: the settings search clears a found key, else
  leaves the field keeping its text; Highlight clears the text, else goes
  back. One rule for both.
- The header always says "Close (Esc)", also on row pages such as
  Highlight, where Esc goes back.
- Reset and "find by key" have no keyboard path (only `handleClick`).
- The Enchantment Order planner takes no key but Esc.

## Next
Fix the Tab bug; agree the Esc and keyboard rules with the maintainer.
