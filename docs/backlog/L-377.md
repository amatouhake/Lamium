# L-377 Search syntax and a key for the search field

Kind: Ready (strong model)
Status: Agreed (maintainer 2026-11-21), not started

The item list's search takes words that must all be in an item's name or
id. It gets a syntax close to what other recipe viewers use (compared on
2026-11-21 from public pages; the comparison stays outside the
repository), a key for the field and a history.

## Decided (maintainer 2026-11-21)
- Words separated by spaces must all match (as now); plain words match the
  name as shown and the id, not the tooltip.
- `-word` leaves out; `a|b` either, read left to right with AND binding
  tighter (`a b | c` is (a and b) or c; no parentheses); `"…"` a phrase
  with spaces, also to search a sign character itself.
- `#word`: in one of the item's tags (`Item::mTags`, as Item details reads
  them, behind the ItemDetails capability; nothing matches where it is
  paused). `$word`: in the item's tooltip text (the game's hover text with
  Lamium's lines). `@word`: the id's namespace, one token whatever it
  holds (an add-on's items). Prefixes combine with `-` (`-#logs`).
- Full-width forms (`－ ｜ ＃ ＄ ＠ ＂`, the ideographic space) read as
  their ASCII signs; hiragana and katakana match each other; with English
  search on, English names match too. No regular expressions.
- Ctrl+F by default puts the cursor in the field (pressed in it, selects
  all). Up and Down in the field step through earlier searches (the
  history the direction item set aside). No right press to clear: the
  usual editing does it (Ctrl+A, Backspace).
- A tip over the field gives the syntax in short.

## Known
- The field already selects all with Ctrl+A and clears a selection with
  Backspace (`ui/TextEdit.h`); not seen in game.
- Tooltip text for every listed item is read a few dozen a frame, as the
  names are; tags once per item.
