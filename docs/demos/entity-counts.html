エンティティ数の内訳と種類別の数

Debug View の「エンティティ」（Java 形式では E:）の合計はそのままに、内訳（プレイヤー・落ちているアイテム・敵対・友好・その他）と、種類ごとの数を足します。数えるものは今の合計と同じ：自分のディメンションでクライアントが持っているエンティティ（サーバーでは近くのものだけ）を 1 秒に 1 回。数はすべて例です。緑の印の行が増える行。

Debug View の表記

決定事項（2026-10-11）：推奨どおり。ただし種類別の数は左の列の最後に置く。円グラフ（Java 版）のような表示は今は過剰なので見送り

  • 内訳の置き場所：A 合計の行のすぐ下に 1 行（推奨。Debug View を開いたときだけ見えればよく、行が 1 つ増えるだけ）。B 合計の行に括弧で続ける（行は増えないが長くなり、ほかの数と混ざる）。C Debug View とは別の HUD 要素（Debug View なしでも出せるが、要素と設定が増える）。
  • 分け方：プレイヤー → 落ちているアイテム → 敵対 → 友好 → その他 の順。重ならないように上から順に当てはめるので、5 つを足すと合計と一致する。敵対はゲームの「モンスター」分類、友好はそれ以外の生き物（動物・村人・ゴーレム・魚・コウモリなど）、その他は生き物でないもの（経験値オーブ、矢などの飛び道具、トロッコ、ボート、防具立て、額縁など）。アイテムはスタックの個数ではなくエンティティの数。
  • 種類別の数：多い順に上位 5 つまたは 10 つ、残りは「ほか N 種類 M」（推奨：オフ / 上位 5 / 上位 10 の選択、既定は上位 5）。置き場所は右の列の下（左の列は座標などで長いため）。名前は Debug View の表記に合わせ、ゲーム標準ではゲーム内の名前、Java 形式では ID（minecraft: は省く）。アドオンのエンティティは名前がなければ ID。
  • 初期値：内訳は Debug View をオンにすれば出る（既定オン、設定でオフにできる）。種類別は既定で上位 5。
  • 分類が実際のゲームで正しく取れるか（サーバーから来たエンティティにも分類が付いているか）は、作ってから確かめる。
