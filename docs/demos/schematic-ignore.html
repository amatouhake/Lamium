Ignored differences: the Check tab, the Ignored button and the HUD

The game checked 10325a18. It was hard to tell which rows were ignored. The button read "無視: 0" with nothing ignored. An ignored difference still showed in the list, the HUD and the nearest-mistake key. This page proposes how each of those should look. It uses one shared example, so Ignore and Undo update every panel. UI text is Japanese, as the game shows it. Strings marked new do not exist yet. Block art and positions are placeholders.

1. Rows and state lines

The unit is one state of one cell. Ignoring a state of a row that has several, such as the repeater's 動力, leaves the row as a yellow wrong-state row, and it still counts. In the detail pane the ignored line stays in place, all dim with a dim "無視中" tag (new), and 戻す sits where 無視 was. Today the line disappears, which is why it is hard to tell what was ignored. A plain button keeps white text, because faint text means disabled.

A cell whose every difference is ignored (the lever) counts as correct. It leaves the chips, the counts, the HUD and the marks. The only real choice is where its row goes:

  • A (recommended): dimmed rows after the mistakes, under a thin divider, shown only when no chip is selected. The kind column reads "無視" in dim with a hollow square. It answers "which rows are ignored" on the screen where they were ignored. Cost: the list holds rows that are not mistakes.
  • B: not listed, like any correct cell. The list stays mistakes only. Cost: the row vanishes when you press 無視, and only the Ignored list shows it again.

2. The Ignored button and its list

The label counts the entries that apply (unchanged). Whether the button shows depends on how many entries the list holds, stale ones included. A stale entry (設計図にない) can only be removed with 戻す, so tying the button to the applied count would leave a stale entry unreachable. Try すべて戻す to reach zero.

  • A (recommended): the button is hidden with no entries. This fixes "無視: 0" directly, and the 無視 buttons on the state lines explain themselves. Cost: the action row changes when the first entry is added, and the "nothing is ignored" hint text is never shown.
  • B: a disabled button: plain, faint, no hover. The layout stays put. Cost: it still reads "無視: 0", only greyed.

The list works as built: it replaces the counts while the button is pressed, shows "ほか N 件" instead of scrolling, and すべて戻す is the two-press destructive button. One addition is proposed: each entry names the file's block as well (-100, 85, -40 レバー · 動力), so you can tell entries apart without walking there. Entries already store the block name.

Open question: with only stale entries left, the button would read "無視: 0" while the list is not empty. Options: show the number of entries in this one case, or accept it, since it is rare.

3. Schematic HUD

An ignored difference counts as matching. When a cell's last difference is ignored, 状態違い drops by one and 正しい rises by one. 最も近い間違い moves on to the next real mistake. No ignored count is added to the HUD: the count stays visible on the Check tab's button.

4. World marks and the nearest-mistake key

A fully ignored cell gets no yellow box, and the key skips it. A partly ignored cell (the repeater) keeps its yellow box. A wrong block in an ignored cell would still be red, because an entry names the file's block. When no mistake is left, the key gives the existing toast 間違いはありません.

To decide
  1. Fully ignored rows in the list: A dimmed after the mistakes, or B not listed.
  2. The Ignored button with no entries: A hidden or B disabled. Either way, its visibility follows the number of entries, stale ones included.
  3. The new "無視中" tag on an ignored state line, and the block name in the Ignored list's entries.
  4. The stale-only case of the label (section 2).
