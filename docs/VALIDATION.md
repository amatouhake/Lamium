# Validation status

What is known to work in game, where, and what has not been checked. One row
per feature, overwritten when a new result arrives. The evidence (builds,
hashes, traces, what the maintainer saw) is in
[VALIDATION-LOG.md](VALIDATION-LOG.md); search it by L-number instead of
reading it whole.

Baseline: Minecraft 1.26.60.05, LeviLamina Client 26.60.4 (Lamium built
against SDK 26.60.4), Windows x64. The version-gated features passed one round
on 1.26.60.05 (L-305) and the SDK 26.60.4 build passed a smoke check. Results
dated 2026-11-06 or later are from 1.26.60.05; earlier results are from
1.26.51.01 on LeviLamina 26.51.x and were not re-run on 1.26.60 unless the row
says so. "Local" is a single-player world, "BDS" a same-machine dedicated
server 1.26.51.1, "server" a server run by others. "Everyday use" is the
maintainer's report from play, without a checklist or a recorded build.
"Through `commit`" names the latest build that confirmed part of the row, not
a re-check of everything listed; a row's newest date does not put its older
items on 1.26.60.05, and "1.26.60.05" on a row means everything listed there
was seen on it.

## Recording a result

Append an entry to the top of VALIDATION-LOG.md (date, commit, DLL SHA-256,
trace options, environment, what was done and seen, what was not covered),
then update the matching row here. Keep this file short: no DLL hashes or
traces; only what is confirmed now (environment, date, the latest confirming
commit) and the open gaps. "Builds and tests pass" is not a game result.
