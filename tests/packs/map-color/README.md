# Map color test packs

A minimal add-on for checking how Lamium's minimap and world map color
add-on blocks (L-324 Map: custom blocks are drawn in a dirt-like brown).
Lamium draws every block by its look (top texture) first and uses the
game's map color only when no look is found; these four blocks tell the
paths apart.

| Block | Texture | `minecraft:map_color` | Lamium's map shows |
| --- | --- | --- | --- |
| `lamiumtest:look_cyan` (A) | bright cyan | `#FF00FF` | cyan (the look wins) |
| `lamiumtest:look_yellow` (B) | bright yellow | none | yellow |
| `lamiumtest:missing_magenta` (C) | name not in `terrain_texture.json` | `#FF00FF` | magenta (no look: map color) |
| `lamiumtest:missing_plain` (D) | name not in `terrain_texture.json` | none | the game's default map color |

Dirt brown anywhere means Lamium averaged the game's missing texture. The
game's map item shows the map color for A and C.

All four are in the creative inventory under Construction, named
"Map test A" to "Map test D".

## Files

`BP/` (behavior pack, depends on the RP) and `RP/` (resource pack) are
generated by `tools/make_packs.py`; edit the script, not the output, and
run `python tests/packs/map-color/tools/make_packs.py`. It writes RGBA
PNGs, blocks with `minecraft:geometry.full_block` next to their
`minecraft:material_instances`, and pack version 2.0.0 with UUIDs of its
own (the first version's packs, 1.0.0, are a different add-on to the
game).

## Install

Copy `BP` into `games/com.mojang/development_behavior_packs/` and `RP` into
`development_resource_packs/` (any folder names). In world settings, enable
"Lamium map color test BP" under Behavior Packs (the RP is added with it).

## Telling a pack load failure

- A and B must show their cyan and yellow faces in the world. The game's
  missing texture (dirt with a "?") on A or B means the RP's textures did
  not load. C and D show that missing texture on purpose.
- A block name like `tile.lamiumtest:look_cyan.name` in the inventory means
  the RP is not applied at all.
- Settings > Creator > Content Log GUI shows pack and block JSON errors when
  the world loads.

The first version of these packs showed the missing texture on both
blocks. Most likely cause: the blocks had `minecraft:material_instances`
but no `minecraft:geometry`, so the game fell back to `blocks.json`, which
the pack does not have (Lamium's log named `textures/blocks/missing_tile`
for both). Not confirmed: no content log was saved.

## What to expect

Place a filled area of each block in a part of the world the map has not
recorded yet (saved tiles keep their old colors until scanned again).
Lamium's log (`mods/Lamium/logs/lamium.log`) has one line per test block
(`add-on block ... from texture | material instance | map color`). Blocks
of the first version (`map_magenta`, `map_none`) placed earlier are unknown
blocks now.
